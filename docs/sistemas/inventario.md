# Inventory system

> Moved from the root `CLAUDE.md` on 2026-11-11, word for word. Keep it in sync with the code; the root keeps only a pointer here.

  - `Inventory` autoload (`scripts/Inventory.gd`) holds `items: Array[InventoryItemData]` and emits `inventory_changed` on every mutation. `_ready()` currently seeds temporary test items (caguama, taco, machete, cinta). Capacity is `CAPACIDAD_BASE` (6) or the `capacidad` of the equipped `mochila` (doesn't take a slot); `add_item` returns false when it doesn't fit (`cabe(item)`). **Stacking** (AG's proposal): consumables (`InventoryItemData.apilable()`: `curacion`, `bolsa_tazo`, `estampita`) share one slot up to `MAX_PILA` (5), the hard maximum per item, with `cantidades` parallel to `items`; `remove_item` takes one unit, `cuantos(item)`/`cantidad(index)` count, `unidades()` is one entry per unit (death bag, missions), `vaciar()` empties. Never touch `items` directly from outside. The `cangurera` (also no slot) is put on through `add_item`; `equipar_mochila` only accepts a bigger backpack (the old one is discarded). `combinar(index_a, index_b)` applies the first matching `RECETAS` entry (`scripts/RecetaData.gd`: `a`, `b`, `resultado`; `resources/recetas/*.tres`).
  - `InventoryItemData` (`scripts/InventoryItemData.gd`) is a `Resource` with name, description, icon, `inspection_model` (a PackedScene whose root must be `Node3D`) , `curacion` (life restored by Utilizar; 0 = not usable), `capacidad` (> 0 = it's a backpack) and `tinte` (alpha > 0 paints the whole model that colour, without its texture: the three backpacks in `resources/productos/mochila*.tres`, 8/10/14 slots, share `mochila.scn`). `crear_modelo(tamano)` returns the model centred and normalized inside a holder node (models come in any unit; long ones are turned sideways). Items are authored as `.tres` files in `resources/`.
  - `Salud` autoload (`scripts/Salud.gd`): `vida` (test value 60 of 100), `vida_max`, signal `cambio`, `estado()` text. Only the inventory changes it for now.
  - `scenes/InventoryUI.tscn` / `scripts/InventoryUI.gd` (instanced in `map_test.tscn`, layer 11, not in `world.tscn`): CanvasLayer with a NAVIGATING/INSPECTING/COMBINING state machine. Tab/Start (`inventory_toggle`) opens it and pauses the tree (it runs with `process_mode` Always), which is what stops `E`/arrows from also moving the player and camera; it won't open while the `jugador` is disabled or its physics stopped (shop, stall close-up, drone). Q/E or left/right cycle items, up/down choose among the commands that apply to the item (Examinar/Utilizar/Combinar), Enter confirms, Esc goes back one step and finally closes. Run alone, it stays open. The look is inspired by Silent Hill 2, not a copy (the user's request), and uses the game's default font and marker yellow: black screen, Estado = the paused game (the view grabbed on opening, cropped below the minimap: it shows where the player is) with `Salud.estado()` as coloured text over it and an SH2-style tint by life fraction (`SHADER_TINTE`: faint green, amber, red that pulses in Grave), Equipo = framed small models (`EQUIPO_CAJAS`, placed with the preview camera's `project_position`) of the weapon `Inventory.arma()` (spins, with name and damage), the backpack with one pip per slot and used/total, the two amulets and the cangurera; a stack shows ×N on its model and in the name; a bottom tab strip (`PESTANAS`: Objetos · Tiliches · Habilidades · Álbum · Libreta · Mapa · Diario, key under each; Diario is `MisionesUI.gd`, J / joypad button 15 (`inventory_journal`): the accepted missions, Enter makes one the active and opens the map on its pointer; unspent points on Habilidades) replaces the old hint line; the Equipo layer and the strip sit under the pages so those cover them; and a row of up to 7 items (`RANURAS`, one model per item in `modelos`, placed by `_lugar`) going back into a black depth fog so they fade with distance. The full-screen 3D preview lives in a SubViewport (not rendered while closed) whose `PreviewWorld` node runs `InventoryInspectViewer.gd` (arrow-key rotation of the centre model, PageUp/PageDown or mouse-wheel zoom).
  - **Paper map**: M or gamepad Select (`inventory_map`) shows `scripts/MapaUI.gd` (state `MAPA`), from the open inventory or straight from the game (`InventoryUI._mapa_directo`: closing it then returns to the game, not the item list). Missing zones are drawn empty, so it opens with no pieces. Nothing else may bind physical M (the safehouse's +$100 is on P), except where `InventoryUI.con_mapa` is false (the tinaco defence uses it for the music). `scripts/map/ZonasMapa.gd` holds 9 hand-drawn zones over `minimapa.png` with shared vertices, so they cover the map exactly. Each zone shows only once you have its piece: `PiezasMapa` autoload (not inventory items, survive fainting, cleared on restart), `scripts/map/PiezaMapa.gd` pickups placed by `Partida._lugares_de_piezas` in front of the interactive store nearest each zone's centre, or beside a lamp post. You start with your spawn zone's piece. `Partida` announces zones as you enter them. Zones are in real-map coordinates, so `Safehouse` sets `piezas_en_el_mapa` false and uses its own test pickup and U key.
  - `scripts/WorldItem.gd`: pickup in group `interactuable` that shows its normalized model and a prompt inside its Area3D; `interact()` equips it (`capacidad` > 0) or adds it to `Inventory` and frees itself, or stays on the ground if it doesn't fit (the prompt says so). `ObjetoPrueba1/2/3` and `MochilaPrueba1/2/3` in `map_test.tscn` are test pickups by the spawn.
