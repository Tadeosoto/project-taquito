# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Guadalajaja" — a Godot 4.7 (Forward Plus, Jolt Physics) third-person 3D prototype with a PS1-style look. All gameplay code is GDScript; there is no build system, linter or test suite. Code comments and in-game UI text are in (informal) Spanish — keep new player-facing strings in Spanish.

## Commands

Godot 4.7 is installed as `godot`.

```bash
godot --path . --editor            # open in the editor
godot --path .                     # run the main scene (scenes/inicio.tscn, the start screen)
godot --path . scenes/InventoryUI.tscn   # run a single scene in isolation
godot --path . --headless --import # (re)import assets / regenerate .godot cache
godot --path . --headless --check-only --script res://scripts/player.gd  # parse-check one script
```

## Architecture

- **Main scene**: `scenes/inicio.tscn` (`scripts/Inicio.gd`): the start screen, a small night scene built in code with the menu over it. Jugar opens the character creator, then loads `scenes/map_test.tscn` in a thread with "Cargando..." on screen; Créditos reads `CREDITS.md` at runtime (add it to the export filter when exporting; the required map attributions are the fallback).
- **Old prototype**: `scenes/world.tscn` is no longer what opens, but still runs by path. It instances `player.tscn`, two `npc.tscn` instances (configured per-instance via exported `tint` and `dialogue`), level geometry from `models/*.glb`, and a `PS1_Postprocess` CanvasLayer whose full-screen ColorRect runs `shaders/dittershader.gdshader` over the screen texture. Render resolution is 640×480 with `viewport` stretch mode and nearest texture filtering — this is intentional for the retro look.
- **Player** (`scripts/player.gd`, `class_name Player`): CharacterBody3D. Movement is camera-relative (`CameraPivot` yaw + `SpringArm3D` pitch); the visual body is the child `Frijol`, which is rotated toward the movement direction separately from the physics body. The `jump` action doubles as "interact": if any node in the `npc` or `interactuable` groups reports `is_player_inside()`, the nearest one gets `interact()` instead of jumping. The player is in group `jugador`. Q/E no longer turn the camera: Q is the `curarse` action (`Player._curarse`: eats the item from `Inventory.mejor_curacion` through `Inventory.usar_curacion`, the same path as the inventory's Utilizar, and locks you for `CURAR_DURA`), E is no longer a weapon key. Both are also `inventory_previous`/`inventory_next`, which only works because the open inventory pauses the tree. Animation is delegated to `Frijol/Modelo` (`scenes/protagonista.tscn`) via duck-typed `update_animation(is_moving, is_airborne, is_sprinting, velocidad)` and the other calls below (`scripts/character_animation.gd`).
- **NPC** (`scripts/npc.gd`): registers itself in group `npc`; `modelo` (set before it enters the tree) swaps the ninja for a `Civiles` model and skips `tint`; a `TalkArea` Area3D detects the `Player`. The interaction prompt and speech bubble are 2D UIs rendered into SubViewports and displayed on `Sprite3D`s. The prompt key label switches between keyboard ("Space") and gamepad ("X") based on the last input device.
- **Inventory system** (read `docs/sistemas/inventario.md` before changing it): the `Inventory` autoload holds `items` (never touch them from outside: stacking, backpack capacity, `combinar` recipes go through its functions), items are `InventoryItemData` `.tres` files in `resources/`, `Salud` holds life, `InventoryUI` (Tab/Start) pauses the tree, M opens the paper map (`MapaUI`, `PiezasMapa`), and `WorldItem` is the pickup.
- **Shaders** (`shaders/`): `ps1_combined.gdshader` merges the three standalone experiments (`jittershader` screen-space vertex snap, `vertex_wobble` view-space snap, `affine_warp` affine UVs) with per-effect toggles — prefer it for new materials.

## Missions

`Misiones` autoload (`scripts/Misiones.gd`): people give missions by day (offers stop at the dusk warning), whether they're played by day or night. Any number wait in the journal (`aceptadas`, no cap) but only `activa` advances (`elegir` switches it, progress is kept). Each `PasoMision.cuando` (DIA, NOCHE, CUALQUIERA) says when that step can be done; outside it the mission waits (no failure, its timer stops), so a night delivery can end with an ENTREGAR to the giver the next day. `MisionData.inicio = LUGAR` missions start at a place (`empezar_en_lugar`), stay out of the journal and push the journal's mission aside until they end. Each mission once per day; it fails when its timer ends. The state survives scene changes: only `Inicio` and the safehouse call `reiniciar()`. The journal is `MisionesUI.gd` (inventory tab, J): Enter makes a mission the active one (`Misiones.elegir`, refused during a LUGAR mission or while `manos_ocupadas`, i.e. carrying the dog) and opens the paper map on its pointer. A step's `carga` is only carried during its hour. Accepting one whose first step is at another hour shows the protagonist's thought on screen (`Supervivencia.avisar`), not a giver line. Important givers have `MisionData.inicial`: while they offer work, `MisionesMundo` lists them in `Misiones.dadores` and `MapaUI`/`MapMinimapa` draw the initial in a white circle (only `medicina_noche` has one, "M", as a test). `scripts/map/MisionesMundo.gd`, created by `Partida`, holds what's in the world: givers (`npc.tscn` using `al_hablar`, a callable returning the line for each press), the objective arrow, delivery spots, the dog (`CosaMision.gd`), the objective line, and the minimap and paper-map targets. **To add a mission without code:** copy a `.tres` in `resources/misiones/` (`MisionData` with `PasoMision` steps: `TENER_OBJETOS`, `ENTREGAR`, `VISITAR`, `RECOGER`) and add it to `Misiones.ARCHIVOS`. Each needs a giver spot (the safehouse's `vecinos` list has one per mission plus the tazos kid), and a new `lugar` keyword or step type needs code in `MisionesMundo`. **Route steps (S2a):** `ESCOLTAR` spawns an `Acompanante` (`scripts/map/Acompanante.gd`: follows the player at 3.6 m/s through `Zombis.campo_jugador` (the flow field, kept running by day while any exists; straight within 3.5 m; teleports next to you if stuck), `vida`, `recibir_golpe`, `cayo`; `Zombie._destino` goes for the nearest one if it's closer than the player) at the giver, until both reach `lugar` (`casas`, `giro:x`, `marca:x`); `LLEVAR_CARGA` is `VISITAR` with `carga` in hand and `pesos_por_entrega` per stop. Both are one-hour steps: `Misiones.ruta_en_curso()` is true while in hour, ending the hour (dawn = police) or `Misiones.desmayo()` (from `Supervivencia._desmayarse`) fails the mission, and `elegir` is refused meanwhile. `Misiones.cambio_de_escena()` (not a bare `es_noche = false`) avoids a false failure on the unknown-hour frame. `DEFENDER` holds `segundos` within 20 m of `lugar` (the clock only runs there, `Misiones.defendiendo`; zero = win) while `Zombis.aparecer_turba(cuantos)` fires every `ola_cada` s; an optional `acompanante` stays put (`Acompanante.quieto`, draws zombies from 22 m) and its fall fails the mission. `CAZAR` puts a red-"!" zombie (`Zombis.sacar`, unalerted) near `lugar` when you're within 70 m (maps show a 25 m area); its death by hits completes the step (`Zombie.cayo_al_amanecer` excludes the dawn fall) and it respawns if lost. `ENTRAR_A` is an arrow at `lugar` (a one-point `VISITAR`); `PasoMision.escena` is reserved for S8's scene change. `ENTRAR_A` with `escena` enters a boss scene through `PasoJefe` (`scripts/mapa/PasoJefe.gd`: `entrar`, `volver(gano)`, flag `desde_juego`; `catrina.tscn` and `lombrices.tscn` check it: with the flag they return to the map on a win or a faint, without it they restart as test scenes) and winning completes the step (`MisionesMundo._resolver_jefe`); `MuroColonia` puts the player back where they entered. Boss entrances are fixed `EntradaJefe` nodes (`scripts/mapa/EntradaJefe.gd`: yellow arrow like a shop, `id`/`escena`/`nombre`, always open; missions point to them with `lugar = "entrada:<id>"`): without the matching ENTRAR_A mission, winning gives no prize and advances nothing (`PasoJefe.hay_premio()`, the boss scenes check it) and only marks the boss beaten; a beaten boss shows a "repetir la pelea" legend and needs the interact key to re-enter. You reappear 4 m in front of the arrow (its +Z). **Vehicles on streets:** `CallesRuta` (`scripts/mapa/CallesRuta.gd`) reads the streets from `textures/map/minimapa.png`: `entre`/`entre_varias` (A*/Dijkstra, 2 m grid), `seguir`, `es_calle`; `ConductorCarro` (`scripts/mapa/ConductorCarro.gd`) drives any +Z-front `Node3D` along such a route (`iniciar`, `llego`, `pausa`, `parar_al_final`). `CAMIONETA` (S11): `CamionetaReparto` (an `Acompanante`) drives house stops at jog speed until before dawn; hordes at stops and while driving (`ola_andando`). `lugar = "salida_colonia"` (Santa Mugre's chofer): accepting cuts to night outside a random colony gate, truck driving (`MuroColonia` closes the colony to `CallesRuta`). The tinaco defence is also an ENTRAR_A scene (`defender_tinaco`, see `scripts/defensa/CLAUDE.md`); in the big map it is offered by Chava at each of the five `SitiosTinaco` tinacos. Test missions: `escolta_noche`, `reparto_noche`, `antena_noche`, `caceria_noche`, `entrada_dia`, `defender_tinaco`, `camioneta_noche`. **Mafia (M7):** `mafia_1`..`8` chain via `MisionData.requiere`/`abierto_de_noche`; `donde`/`lugar` `punto:<origen>` (giver and delivery beside the door, off the store arrow); `PasoMision.soltable` box: attack drops it, Space picks it up; 5 deliveries open La Gotera (`Misiones.favela_abierta`). Detail in `docs/misiones.md`. Police slang: cuicos, cerdos, marranos (not "blancos"). `Player.cargar`/`soltar_carga` show something held, with `Walk_Carry`. Stepping onto a store's yellow arrow enters the store, so tests must stand beside it.

## Conventions / gotchas

- **PS1 vertex snapping is only for characters and props.** World shaders `#define PS1_MUNDO` before including `ps1_vertex.gdshaderinc`, which skips it; world materials on `ps1_combined` set `jitter_enabled` and `wobble_enabled` false; `MapStreamer._quitar_brinco` does it for the baked chunk materials. Pieces stuck to each other (paint, trim, graffiti) jumped against each other otherwise.
- `Player._process` smooths only the visible model and camera between the last two physics positions (`Engine.get_physics_interpolation_fraction`), because the body moves 60 times a second and the screen more often. Project-wide physics interpolation is off. `godot --path . tools/medir_mapa.tscn -- --movimiento` measures it (`--sin-suavizar` to compare).
- `ps1_suelo` floors overlap at the same height in the baked map, so each type gets a depth layer (`SueloPasto.capa`, set by `MapStreamer._quitar_brinco`): asphalt, cobbles, sidewalk, grass, dirt.
- After adding a `class_name`, run `godot --path . --headless --import` once, or headless runs won't find the class. A headless run with a parse error sits idle forever, so give test runs a time limit.

- PS1 shaders must write `POSITION` unconditionally (`ps1_vertex()` returns the unsnapped clip position when `jitter_enabled` is false). A spatial shader that writes `POSITION` only inside an `if` leaves the mesh invisible when the branch isn't taken. The original `ps1_combined` had this bug; `shaders/jittershader.gdshader` still does. Huge meshes (the 1900 m `Suelo`) need jitter/wobble off, otherwise vertex snapping distorts them near the camera.
- `pkill -f <pattern>` from the Bash tool also kills the tool's own shell when the pattern appears in the command line; use a pattern that can't match itself (e.g. `fetch_sat[e]lite`).
- Chunk `visibility_range_end` is 250 m plus half the chunk's AABB diagonal, because Godot measures it to the AABB center and some chunks are 800+ m wide.
- Input actions are defined in `project.godot` (`move_*`, `camera_*`, `jump`, `sprint`, `inspect_*`, `inventory_*`). Note Q/E are bound to both `curarse`/`cambiar_arma` and `inventory_previous`/`inventory_next`, and arrow keys to `move_*`, `inspect_*` and (left/right) `inventory_next`/`inventory_previous`. These only coexist because the open inventory pauses the tree; don't open a menu using them without pausing.
- Resources are referenced by `uid://`; keep each `.gd.uid` file alongside its script when moving/renaming, or edit via the Godot editor.
- `scenes/world.tscn` and `scripts/Inventory.gd.uid` are listed in `.gitignore` but are already tracked, so changes to them still show up in git.
- `scenes/InventoryUI.tscn*.tmp` files are editor save leftovers, not real scenes.
- **Rules that cross systems** (their detail is in `docs/sistemas/` or the folder `CLAUDE.md`s, repeated here so they're never missed):
  - **Skin tone only changes how the world treats you** (prices, mission pesos, lines). Combat, zombie drops and fruit machines must stay out of it; a darker character is never weaker.
  - **JJ owns the player's attack code** (`scripts/player.gd`, `character_animation.gd`, `Player.atrapar`, `_radio_de`, `EfectosPixel`'s `golpe` slot, `Personaje.vestir`): tell the user before changing it, so they can check with JJ.
  - Skeletons are retargeted to `%GeneralSkeleton` with profile bone names (`Hips`, `RightHand`...): find them by class (`find_children("*", "Skeleton3D")`), not with `find_child("Skeleton3D")`.
  - A `SkeletonModifier3D`'s result only exists after the modifiers run: measure it in `Skeleton3D.skeleton_updated`, not in `_physics_process`.
  - Timing under the hit freeze uses `Time.get_ticks_msec()`: a `SceneTreeTimer` stayed stuck for seconds at that time scale, even with `ignore_time_scale`.
  - A new sound name must also go into `DefensaTinaco.SONIDOS`, or that scene plays nothing for it (`Sonidos.solo`).
  - A node re-enables `_physics_process` when it becomes ready if its script defines it: call `set_physics_process(false)` after `add_child`.
  - **When you add a mechanic, add it to the safehouse too.**

## graphify (narrative graph)

`docs/graphify-out/` holds a knowledge graph of the six narrative docs (`lore`, `personajes`, `misiones`, `items`, `especificaciones`, `revision-historia`): 458 nodes, 22 communities (rebuilt 2026-11-11), built by `/graphify`. `docs/graphify-out/.graphify_build.json` excludes the rest of `docs/` (mapa, prompts, pruebas, notes, `mejoras.md`) so an update stays on those six (the skill is in `.claude/skills/graphify/`). Install with `uv tool install graphifyy`.

**Code graph** (`scripts/graphify-out/`, 2026-11-12): graphify has no GDScript parser, so `tools/graphify_gdscript.py` extracts `scripts/**/*.gd` and the `.tscn` that use them with regexes (files, functions, signals, `class_name`/autoload calls, preload/load, extends) and runs graphify's build/cluster/report. No LLM, ~7 s. Rebuild with `"$(cat docs/graphify-out/.graphify_python)" tools/graphify_gdscript.py` (not `graphify update`). Query with `--graph scripts/graphify-out/graph.json`. It misses calls through variables, `call()`/groups and editor-connected signals. A `.gdignore` keeps Godot from importing it.

- For a story question, ask the graph before reading a whole doc, from the repo root: `graphify query "<question>" --graph docs/graphify-out/graph.json`; `graphify explain "<node>"` and `graphify path "<A>" "<B>" --undirected` take the same `--graph`. Then read only the sections it names (each node carries its doc and heading). Every narrative skill, `/game-quest`, `/game-lore` and the `narrative-writer` agent say this in their adaptation block; keep it in any new one.
- `docs/graphify-out/graph.html` is the browsable view and `GRAPH_REPORT.md` the summary (hubs, communities, loose ends).
- The graph is a snapshot: when it disagrees with a doc, the doc wins. After editing a narrative doc, rebuild with `/graphify docs --update` (re-extracts only changed files; `graphify update` is AST-only and does not reread docs). Run it from `docs/`, so the output stays in `docs/graphify-out/`. Cross-doc node ids were reconciled by hand on the first build (accents, full character names; lore's copies of characters merged into `personajes_*`), so check for dangling edges after an update.
- `.graphify_python` and `.graphify_root` are per-machine and gitignored. A rebuilt `graph.json` is rewritten whole, so a large diff to it is expected.
