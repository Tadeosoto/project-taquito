# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Guadalajaja" — a Godot 4.7 (Forward Plus, Jolt Physics) third-person 3D prototype with a PS1-style look. All gameplay code is GDScript; there is no build system, linter or test suite. Code comments and in-game UI text are in (informal) Spanish — keep new player-facing strings in Spanish.

## Commands

Godot 4.7 is installed as `godot`.

```bash
godot --path . --editor            # open in the editor
godot --path .                     # run the main scene (scenes/inicio.tscn, the start screen)
godot --path . scenes/InventoryUI.tscn   # run a single scene in isolation
godot --path . --headless --import # (re)import assets / regenerate .godot cache
godot --path . --headless --check-only --script res://scripts/player.gd  # parse-check one script
```

## Architecture

- **Main scene**: `scenes/inicio.tscn` (`scripts/Inicio.gd`): the start screen, a small night scene built in code with the menu over it. Jugar opens the character creator, then loads `scenes/map_test.tscn` in a thread with "Cargando..." on screen; Créditos reads `CREDITS.md` at runtime (add it to the export filter when exporting; the required map attributions are the fallback).
- **Old prototype**: `scenes/world.tscn` is no longer what opens, but still runs by path. It instances `player.tscn`, two `npc.tscn` instances (configured per-instance via exported `tint` and `dialogue`), level geometry from `models/*.glb`, and a `PS1_Postprocess` CanvasLayer whose full-screen ColorRect runs `shaders/dittershader.gdshader` over the screen texture. Render resolution is 640×480 with `viewport` stretch mode and nearest texture filtering — this is intentional for the retro look.
- **Player** (`scripts/player.gd`, `class_name Player`): CharacterBody3D. Movement is camera-relative (`CameraPivot` yaw + `SpringArm3D` pitch); the visual body is the child `Frijol`, which is rotated toward the movement direction separately from the physics body. The `jump` action doubles as "interact": if any node in the `npc` or `interactuable` groups reports `is_player_inside()`, the nearest one gets `interact()` instead of jumping. The player is in group `jugador`. Q/E no longer turn the camera: Q is the `curarse` action (`Player._curarse`: eats the item from `Inventory.mejor_curacion` through `Inventory.usar_curacion`, the same path as the inventory's Utilizar, and locks you for `CURAR_DURA`), E is no longer a weapon key. Both are also `inventory_previous`/`inventory_next`, which only works because the open inventory pauses the tree. Animation is delegated to `Frijol/Modelo` (`scenes/protagonista.tscn`) via duck-typed `update_animation(is_moving, is_airborne, is_sprinting, velocidad)` and the other calls below (`scripts/character_animation.gd`).
- **Protagonist and retargeting** (branch `protagonista-compa`): the player is `el_compa` (`models/personajes/protagonistas/el_compa/`, hombre_04 of the PSX pack repainted by `tools/personajes/el_compa.gd`), at scale 0.39 (~1.8 m), with Quaternius's UAL1/UAL2 clips (CC0). Every skeleton is retargeted on import to `SkeletonProfileHumanoid` (`retarget/bone_map` plus `fix_silhouette` in each `.import`'s `_subresources`; the Mixamo pack is T-pose and Quaternius A-pose, so without `fix_silhouette` the elbows flared): the bone maps are `resources/personajes/huesos_{mixamo,rigify,unreal}.tres`, written by `tools/personajes/mapas_huesos.gd`, and the result is a `%GeneralSkeleton` with profile bone names (`Hips`, `RightHand`...). **`find_child("Skeleton3D")` no longer finds it: search by class** (`find_children("*", "Skeleton3D")`). `tools/personajes/animaciones.gd` gathers the clips into `resources/personajes/animaciones_humanas.res` (dropping tracks for bones el_compa lacks); add a clip to `CLIPS` there and rerun, then `--import`. `character_animation.gd` builds an `AnimationTree` in code: feet (Idle/Jog_Fwd/Sprint/Walk_Carry/Jump, time-scaled by real speed), the pistol on the upper body only (Pistol_Idle, or a Pistol_Aim Down/Neutral/Up blend by aim height, kicked up per shot), a reload one-shot, a full-body action one-shot (the sword swings, Hit_Chest) and Death01 held on the floor. Transitions start with no state (T-pose) unless one is requested, which `_ready` does. The 41 civilians (`pack_psx/hombre_*`, `mujer_*`) get the same retarget (`tools/personajes/retarget_civiles.gd` writes it into their `.import`) and 40 of them are placed by `scripts/personajes/Civiles.gd` (`mujer_01` is left out: the pack has no texture for her and she rendered all white; static: `poner(padre, nombre, clip)` at scale 0.39 with the clip library `"h"`, `elegir(semilla)` for a fixed pick, `calentar()` threaded loads from `MapPuntos._calentar`; the scenes stay in a static cache, because without a held reference each `load()` re-read the model from disk, ~3.5 ms per seller while walking). Other NPCs still use the ninja (`models/ninja_male.fbx`, clips looked up by suffix because the FBX prefixes them).
- **NPC** (`scripts/npc.gd`): registers itself in group `npc`; `modelo` (set before it enters the tree) swaps the ninja for a `Civiles` model and skips `tint`; a `TalkArea` Area3D detects the `Player`. The interaction prompt and speech bubble are 2D UIs rendered into SubViewports and displayed on `Sprite3D`s. The prompt key label switches between keyboard ("Space") and gamepad ("X") based on the last input device.
- **Inventory system**:
  - `Inventory` autoload (`scripts/Inventory.gd`) holds `items: Array[InventoryItemData]` and emits `inventory_changed` on every mutation. `_ready()` currently seeds temporary test items (caguama, taco, machete, cinta). Capacity is `CAPACIDAD_BASE` (6) or the `capacidad` of the equipped `mochila` (doesn't take a slot); `add_item` returns false when full and `equipar_mochila` only accepts a bigger backpack (the old one is discarded). `combinar(index_a, index_b)` applies the first matching `RECETAS` entry (`scripts/RecetaData.gd`: `a`, `b`, `resultado`; `resources/recetas/*.tres`).
  - `InventoryItemData` (`scripts/InventoryItemData.gd`) is a `Resource` with name, description, icon, `inspection_model` (a PackedScene whose root must be `Node3D`) , `curacion` (life restored by Utilizar; 0 = not usable), `capacidad` (> 0 = it's a backpack) and `tinte` (alpha > 0 paints the whole model that colour, without its texture: the three backpacks in `resources/productos/mochila*.tres`, 8/10/14 slots, share `mochila.scn`). `crear_modelo(tamano)` returns the model centred and normalized inside a holder node (models come in any unit; long ones are turned sideways). Items are authored as `.tres` files in `resources/`.
  - `Salud` autoload (`scripts/Salud.gd`): `vida` (test value 60 of 100), `vida_max`, signal `cambio`, `estado()` text. Only the inventory changes it for now.
  - `scenes/InventoryUI.tscn` / `scripts/InventoryUI.gd` (instanced in `map_test.tscn`, layer 11, not in `world.tscn`): CanvasLayer with a NAVIGATING/INSPECTING/COMBINING state machine. Tab/Start (`inventory_toggle`) opens it and pauses the tree (it runs with `process_mode` Always), which is what stops `E`/arrows from also moving the player and camera; it won't open while the `jugador` is disabled or its physics stopped (shop, stall close-up, drone). Q/E or left/right cycle items, up/down choose among the commands that apply to the item (Examinar/Utilizar/Combinar), Enter confirms, Esc goes back one step and finally closes. Run alone, it stays open. The look is inspired by Silent Hill 2, not a copy (the user's request), and uses the game's default font and marker yellow: black screen, Estado = the paused game (the view grabbed on opening, cropped below the minimap, not tinted: it shows where the player is) with `Salud.estado()` as coloured text over it, Equipo = the backpack model and used/total count, and a row of up to 7 items (`RANURAS`, one model per item in `modelos`, placed by `_lugar`) going back into a black depth fog so they fade with distance. The full-screen 3D preview lives in a SubViewport (not rendered while closed) whose `PreviewWorld` node runs `InventoryInspectViewer.gd` (arrow-key rotation of the centre model, PageUp/PageDown or mouse-wheel zoom).
  - **Paper map**: M or gamepad Select (`inventory_map`) shows `scripts/MapaUI.gd` (state `MAPA`), from the open inventory or straight from the game (`InventoryUI._mapa_directo`: closing it then returns to the game, not the item list). Missing zones are drawn empty, so it opens with no pieces. Nothing else may bind physical M (the safehouse's +$100 is on P), except where `InventoryUI.con_mapa` is false (the tinaco defence uses it for the music). `scripts/map/ZonasMapa.gd` holds 9 hand-drawn zones over `minimapa.png` with shared vertices, so they cover the map exactly. Each zone shows only once you have its piece: `PiezasMapa` autoload (not inventory items, survive fainting, cleared on restart), `scripts/map/PiezaMapa.gd` pickups placed by `Partida._lugares_de_piezas` in front of the interactive store nearest each zone's centre, or beside a lamp post. You start with your spawn zone's piece. `Partida` announces zones as you enter them. Zones are in real-map coordinates, so `Safehouse` sets `piezas_en_el_mapa` false and uses its own test pickup and U key.
  - `scripts/WorldItem.gd`: pickup in group `interactuable` that shows its normalized model and a prompt inside its Area3D; `interact()` equips it (`capacidad` > 0) or adds it to `Inventory` and frees itself, or stays on the ground if it doesn't fit (the prompt says so). `ObjetoPrueba1/2/3` and `MochilaPrueba1/2/3` in `map_test.tscn` are test pickups by the spawn.
- **Shaders** (`shaders/`): `ps1_combined.gdshader` merges the three standalone experiments (`jittershader` screen-space vertex snap, `vertex_wobble` view-space snap, `affine_warp` affine UVs) with per-effect toggles — prefer it for new materials.

## Danger: day/night, zombies, fighting, fainting (`map_test.tscn`)

- `scripts/map/Ciclo.gd` (`Ciclo` node): 12 min day + 8 min night by default (`map_test` uses 8 + 6, JJ's call), 30 s transitions, starting 60 s into the day; signals `aviso_atardecer` (1 min before), `anochecio`, `amanecio`. **N** jumps to the next dusk or dawn. `hora()` is the clock, running at one even rate (so with less night than day it gets dark late): dawn's midpoint (`amanecio`) is `HORA_AMANECER` 6:00, and with 8 + 6 min dusk is 19:42. `Partida` shows it bottom left with "Día n" / "Noche n/3". It drives `Alumbrado.configurar_noche`, sun, ambient and fog. `locales_preview.tscn` still uses the instant `MapNocheDebug.gd`.
- `scripts/map/Zombis.gd` (`Zombis` node): places zombies 24-36 m from the player, on the street (downward ray, `ALTO_CALLE`) and out of camera, from a pool of `max_total` (30) pre-built ones (`Zombie.despertar`/`dormir`, never `new`/`queue_free` except the boss). Loose ones: every 3 s, max 2 + `Deterioro.zona` × 8 + 1 per night after the first, capped at 12. Total cap 30. Removes those beyond 70 m; all collapse at dawn. Spawns stop while the player is frozen.
- `scripts/map/Director.gd`: L4D-style pacing, decides when zombies spawn. `intensidad` rises with damage and nearby kills and decays when nobody is attacking; states ARMANDO → SOSTENER → BAJANDO → RESPIRO. Mobs (`aparecer_turba`, `Zombie.cazador`: faster, always hunt the player) come every 90-180 s during ARMANDO, only where `Zombis.turbas` is on and there's no `ritmo`.
- **Night rhythm** (`scripts/map/RitmoNoche.gd`, a Resource; `map_test` and the safehouse use `resources/zombis/noche_mapa.tres` as `Zombis.ritmo`): JJ wants nights where you can do night objectives, not constant killing (the tinaco defence is the frantic one, ~80 kills; a 6 min map night should be ~30). With `ritmo`, `Zombis._seguir_ritmo` replaces the Director's spawning: `calma_inicial` quiet seconds, then groups of `grupo` 1-2 loose ones from one side every `cada_entero`..`cada_destruido` seconds (lerped by `Deterioro.relativo`, 0 = the least ruined block, 1 = the most), never more than `vivos_entero`..`vivos_destruido` loose alive, `mas_por_noche` more often each night; and `turbas` 1-2 mobs per night of `turba` 7-8 hunters in a tight ball (`turba_abre`) at random times between `turba_desde` and `turba_hasta` of the night, `turba_separadas` apart. The Director still tracks intensity and, with `respetar_director`, pauses loose spawns during its RESPIRO. Every number is in the `.tres` for tuning by playing: at dawn `Partida` shows how many came out and how many you killed (`Zombis.salieron_noche`/`muertos_noche`/`turbas_noche`, also printed with the mob times). In the safehouse the loose ones still go for the Refugio's tinaco unless you're within 12 m. Timings come from secondary sources on Valve's talk; the numbers are for tuning by playing.
- `scripts/map/CampoFlujo.gd`: street pathing for zombies, a 48 m flow field filled breadth-first and asked of physics (layer 1) cell by cell with a per-frame budget. A cell is blocked if its box query **or** one of four rays across it (`_cruza_pared`, back faces on) hits: the baked chunks' hollow `ConcavePolygonShape3D` buildings were only half seen by the box, so the field led zombies into a wedge between one and the barricade. One to the player and one to the refuge entries. Barricades (layer 3) aren't obstacles, so paths lead up to them. `direccion()` snaps to 8 directions on a 1.25 m grid (BFS over 4 neighbours, so paths are staircases); walking uses `direccion_suave()` (bilinear over the 4 surrounding cells) and `adelante(punto, pasos)` (follows the field N cells, for the zombie's look-ahead).
- `scripts/map/Zombie.gd`: 30 life, 3-5 m/s. **Two types** (`Zombie.Tipo`):
  - **NORMAL** is the one that spawns. It gets a random skin from `Zombie.SKINS`: `zombie_psx` or `pack_psx/monstruo_00..03`. Each entry carries a scale so the head ends up at ~1.62 m. `Zombie.modelo_skin()` builds one, and the start screen uses it too.
  - **The skins can't use the gordo's clips**: those belong to his own 3ds Max skeleton. Instead the skins are retargeted like the civilians: the monsters through `retarget_civiles.gd`'s `EXTRA`, `zombie_psx` through its own `huesos_zombie_psx.tres`, because its gltf numbers every bone; it was re-baked with `hornear_modelos.gd -- --solo=zombie_psx`. They play Quaternius's `Zombie_Idle`/`Zombie_Walk_Fwd`/`Zombie_Scratch` plus `Jog_Fwd`/`Sprint`/`Hit_Chest`/`Death01` (`CLIPS_SKIN`; `_animar` maps the old names).
  - The scratch lands at ~0.6 s of the clip, so `ATAQUE_VELOCIDAD_SKIN` 0.9 keeps the hit at `GOLPE_EN`.
  - **GORDO** (`zombie_gordo`, its own clips) is a separate type whose attacks and stats JJ will define later (`GORDO_*`, a copy of the normal ones for now). Nothing spawns it yet, so the hordes have no gordos. The boss still uses the gordo model.
  - **Wander, then run** (JJ): a normal one spawns with `alerta` false and wanders, walking at `DEAMBULA_VEL` 0.8 m/s to a random point a few metres away, stopping and picking another; no flow field. Every `TICKS_DETECTA` it checks whether it detects you:
    - it sees you within `VE_DESDE` 25 m, in a 120° front cone, with one ray from its eyes not blocked (the player is on layer 1, so the ray excludes it);
    - it hears you within `OYE_DESDE` 12 m, facing any way;
    - you hit it.
  - Pistol shots call `Zombie.ruido(punto, OYE_DISPARO 40 m)`, which alerts every awake zombie in range; a future crossbow won't, which is its point.
  - `alertar()` growls and alerts those within `CONTAGIA` 8 m.
  - Once alerted, it behaves as before and runs at the same 3-5 m/s: `Jog_Fwd`, or `Sprint` from `CORRE_DESDE` by its base speed, scaled by `PASO_SKIN` so it doesn't slide, and idle when stopped (`QUIETO`). The alert lasts until it goes back to the pool.
  - These spawn already alerted: hunters, mob members (`Zombis._sacar_de_turba`), the gordo and boss, and everyone in the tinaco defence (`_tinaco` present).
  - Follows `CampoFlujo` to its target, straight when close or outside the field, sidesteps when stuck, hits for 12, gives $1-3 when killed. A life bar floats above it (`shaders/barra_vida.gdshader`, billboard, one shared material, life as an instance uniform, hidden past `BARRA_HASTA` 35 m and on death). Collision layer 2, mask 1 + 2 + 3, so zombies are solid to each other. `move_and_slide` alone still let them overlap, so `Zombis._no_encimar` separates pairs after everyone has moved (`process_physics_priority`, `Zombie.apartarse` collides with walls only). Near its target, a zombie blocked by another waits instead of sidestepping. Doesn't act while the player is frozen.
- **Swarm walking** (`Zombie.enjambre`, on by default; Alan's report that they walked in single file, robotic). Every field lookup used to give every zombie in a cell the same snapped vector, applied straight to velocity, so they all took one staircase line. Now, in `_decidir`: it follows the field `ADELANTE` 8 cells ahead (`ADELANTE_CERCA` 4 as fallback) and walks straight to that point if three rays (`_se_ve`: both body edges **and** the centre, a barrel fit between two) see it, rechecked every `TICKS_VISTA`; otherwise `direccion_suave`. Each zombie has a lane (`_carril` × `CARRIL` 1.5 m plus a `VAIVEN` sway) applied to the aim point, faded within `CARRIL_DESDE` of its target or gap; blocked by another zombie far from the target it moves its lane to the free side (`REBASA`). Turning is gradual (`_rumbo` `move_toward` `_deseado` at `ACELERA`). Speed varies ±`VEL_VAIVEN` with random bursts (`ARRANQUE`). Hitting a wall head-on it slides along it at once (`_rozar_pared`, `DE_FRENTE`) instead of waiting to count as stuck: that and the centre ray removed the sidesteps against barrels. Within `DERECHO` of a pass-through target (gap, refuge entry: `_blanco` null) it only goes straight if it sees it (`_meta_se_ve`); arriving from the side, a barricade piece's end stopped it dead. The boss gets only the gradual turning. Off, it's the old walking exactly (0 in the safehouse). Same frame cost as before; numbers in `docs/pruebas-enjambre.md` (measured with headless test scenes that lived only in the `enjambre` branch).
- **Melee feel**: each hit flashes the zombie white (`Zombie._pintar_blanco`), plays `whack`, blasts dirty water along the hit (`scripts/map/Liquido.gd`: drops simulated in GDScript, drawn by two shared MultiMeshes, starting inside the body, hanging during the freeze, stretching in flight and leaving splats on landing that fade after 15 s; caps of 256 drops and 60 splats; found through group `liquido`), doesn't knock it back (`Zombie.EMPUJON` 0: Alan asked for ~0.5 m, but it pushed zombies out of reach and the combo missed its second hit, so JJ removed it; if raised, it goes into `_retroceso`, added to `velocity` in any live state and braked by `EMPUJON_FRENA`) and never stuns it: `Zombie.ATURDIR` is false because stunned zombies almost never hit JJ (8th defence test). With it true, melee stuns on `ATURDE_PROB` 20 % even while walking, plus the timed-hit window below. The pistol passes `cuerpo_a_cuerpo` false to `recibir_golpe`, so it neither pushes nor stuns. The boss's `JEFE_ARRASTRE` is still 0 and it's never stunned. **Timed hits** (`Player.pelea_a_tiempo`, toggled with 9 in the safehouse): a zombie starting an attack growls (no red tint: JJ didn't want it; the growl and the animation are the tell), and for `Zombie.CORTE` (0.3 s) a hit in that window stuns it (`HERIDO_DURA`) only while `ATURDIR` is on; otherwise the growl is just the cue to step away. You're only locked until your hit lands (`ATAQUE_QUIETO_A_TIEMPO`); moving after that fades the swing out (`soltar_golpe`) and resets the combo. Off, it's the previous test: never stunned, locked for the whole sweep and would bounce the player (`_retroceso`, added only around `move_and_slide` because braking overwrites `velocity`; `RETROCESO` is 0 at JJ's request, the getting-hit push below still uses it), shakes the camera (`h_offset`/`v_offset`) and freezes (`Player._congelar`, which restores the previous `Engine.time_scale`, not 1, so a sped-up test night survives hits). Force scales with weapon damage. One whack, shake and freeze per swing however many it hits. A player kill swells the zombie white during the freeze, then it bursts (`Zombie._reventar`): water, scraps, `reventar`, a shrinking puddle. The burst leans along the killing hit (`_al_morir`; `REVIENTA_AL_FRENTE` of the drops go that way, the rest all round) and `RestosZombi` lands `Zombis.RESTOS_LANZA` 1.2 m that way. A pistol kill freezes only that zombie (white, animation paused) for `CONGELA_PISTOLA_MS` 60 before swelling (`_hinchar_en`); the world never slows on shots. A **headshot kill** (`cabeza`, not the boss) scales the `Head` bone to ~0 (`_escalar_hueso`, restored in `_restaurar` for the pool), sprays dirty water up from the `Neck` bone for `FUENTE_MS` 1000 (`_chorro` through `Liquido`, plus the `fuente` pixelfx slot), then swells and bursts. Dawn deaths still fall. **Timing uses `Time.get_ticks_msec()` and the freeze is released by `Player.RelojCongelada`, a child that always processes: a `SceneTreeTimer` stayed stuck for seconds at this time scale, even with `ignore_time_scale`.** `Partida._ganar` waits `GANAR_ESPERA` so the boss's burst is seen before the pause. ## Character (`scripts/Personaje.gd`)

## Conventions / gotchas

- **PS1 vertex snapping is only for characters and props.** World shaders `#define PS1_MUNDO` before including `ps1_vertex.gdshaderinc`, which skips it; world materials on `ps1_combined` set `jitter_enabled` and `wobble_enabled` false; `MapStreamer._quitar_brinco` does it for the baked chunk materials. Pieces stuck to each other (paint, trim, graffiti) jumped against each other otherwise.
- `Player._process` smooths only the visible model and camera between the last two physics positions (`Engine.get_physics_interpolation_fraction`), because the body moves 60 times a second and the screen more often. Project-wide physics interpolation is off. `godot --path . tools/medir_mapa.tscn -- --movimiento` measures it (`--sin-suavizar` to compare).
- `ps1_suelo` floors overlap at the same height in the baked map, so each type gets a depth layer (`SueloPasto.capa`, set by `MapStreamer._quitar_brinco`): asphalt, cobbles, sidewalk, grass, dirt.
- After adding a `class_name`, run `godot --path . --headless --import` once, or headless runs won't find the class. A headless run with a parse error sits idle forever, so give test runs a time limit.

- PS1 shaders must write `POSITION` unconditionally (`ps1_vertex()` returns the unsnapped clip position when `jitter_enabled` is false). A spatial shader that writes `POSITION` only inside an `if` leaves the mesh invisible when the branch isn't taken. The original `ps1_combined` had this bug; `shaders/jittershader.gdshader` still does. Huge meshes (the 1900 m `Suelo`) need jitter/wobble off, otherwise vertex snapping distorts them near the camera.
- `pkill -f <pattern>` from the Bash tool also kills the tool's own shell when the pattern appears in the command line; use a pattern that can't match itself (e.g. `fetch_sat[e]lite`).
- Chunk `visibility_range_end` is 250 m plus half the chunk's AABB diagonal, because Godot measures it to the AABB center and some chunks are 800+ m wide.
- Input actions are defined in `project.godot` (`move_*`, `camera_*`, `jump`, `sprint`, `inspect_*`, `inventory_*`). Note Q/E are bound to both `curarse`/`cambiar_arma` and `inventory_previous`/`inventory_next`, and arrow keys to `move_*`, `inspect_*` and (left/right) `inventory_next`/`inventory_previous`. These only coexist because the open inventory pauses the tree; don't open a menu using them without pausing.
- Resources are referenced by `uid://`; keep each `.gd.uid` file alongside its script when moving/renaming, or edit via the Godot editor.
- `scenes/world.tscn` and `scripts/Inventory.gd.uid` are listed in `.gitignore` but are already tracked, so changes to them still show up in git.
- `scenes/InventoryUI.tscn*.tmp` files are editor save leftovers, not real scenes.

## graphify (narrative graph)

`docs/graphify-out/` holds a knowledge graph of the six narrative docs (`lore`, `personajes`, `misiones`, `items`, `especificaciones`, `revision-historia`): 367 nodes, 12 communities, built by `/graphify` (the skill is in `.claude/skills/graphify/`). There is no graph of the code. Install with `uv tool install graphifyy`.

- For a story question, ask the graph before reading a whole doc, from the repo root: `graphify query "<question>" --graph docs/graphify-out/graph.json`; `graphify explain "<node>"` and `graphify path "<A>" "<B>" --undirected` take the same `--graph`. Then read only the sections it names (each node carries its doc and heading). Every narrative skill, `/game-quest`, `/game-lore` and the `narrative-writer` agent say this in their adaptation block; keep it in any new one.
- `docs/graphify-out/graph.html` is the browsable view and `GRAPH_REPORT.md` the summary (hubs, communities, loose ends).
- The graph is a snapshot: when it disagrees with a doc, the doc wins. After editing a narrative doc, rebuild with `/graphify docs --update` (re-extracts only changed files; `graphify update` is AST-only and does not reread docs). Run it from `docs/`, so the output stays in `docs/graphify-out/`. Cross-doc node ids were reconciled by hand on the first build (accents, full character names; lore's copies of characters merged into `personajes_*`), so check for dangling edges after an update.
- `.graphify_python` and `.graphify_root` are per-machine and gitignored. A rebuilt `graph.json` is rewritten whole, so a large diff to it is expected.
