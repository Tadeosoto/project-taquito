# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Guadalajaja" — a Godot 4.7 (Forward Plus, Jolt Physics) third-person 3D prototype with a PS1-style look. All gameplay code is GDScript; there is no build system, linter or test suite. Code comments and in-game UI text are in (informal) Spanish — keep new player-facing strings in Spanish.

## Commands

Godot 4.7 is installed as `godot`.

```bash
godot --path . --editor            # open in the editor
godot --path .                     # run the main scene (scenes/inicio.tscn, the start screen)
godot --path . scenes/InventoryUI.tscn   # run a single scene in isolation
godot --path . --headless --import # (re)import assets / regenerate .godot cache
godot --path . --headless --check-only --script res://scripts/player.gd  # parse-check one script
```

## Architecture

- **Main scene**: `scenes/inicio.tscn` (`scripts/Inicio.gd`): the start screen, a small night scene built in code with the menu over it. Jugar opens the character creator, then loads `scenes/map_test.tscn` in a thread with "Cargando..." on screen; Créditos reads `CREDITS.md` at runtime (add it to the export filter when exporting; the required map attributions are the fallback).
- **Old prototype**: `scenes/world.tscn` is no longer what opens, but still runs by path. It instances `player.tscn`, two `npc.tscn` instances (configured per-instance via exported `tint` and `dialogue`), level geometry from `models/*.glb`, and a `PS1_Postprocess` CanvasLayer whose full-screen ColorRect runs `shaders/dittershader.gdshader` over the screen texture. Render resolution is 640×480 with `viewport` stretch mode and nearest texture filtering — this is intentional for the retro look.
- **Player** (`scripts/player.gd`, `class_name Player`): CharacterBody3D. Movement is camera-relative (`CameraPivot` yaw + `SpringArm3D` pitch); the visual body is the child `Frijol`, which is rotated toward the movement direction separately from the physics body. The `jump` action doubles as "interact": if any node in the `npc` or `interactuable` groups reports `is_player_inside()`, the nearest one gets `interact()` instead of jumping. The player is in group `jugador`. `girar_con_qe` (on only in `map_test.tscn`) turns the camera with physical Q/E; it isn't an input action because Q is `inventory_previous` in `world.tscn`. Animation is delegated to `Frijol/Ninja` via duck-typed `update_animation(is_moving, is_airborne, is_sprinting)` (`scripts/character_animation.gd`).
- **Animation clips** are looked up by suffix (`"Idle"` matches `"...|Idle"`) because the imported FBX (`models/ninja_male.fbx`) prefixes clip names; loop mode is forced in code. Both player and NPC share this model.
- **NPC** (`scripts/npc.gd`): registers itself in group `npc`; a `TalkArea` Area3D detects the `Player`. The interaction prompt and speech bubble are 2D UIs rendered into SubViewports and displayed on `Sprite3D`s. The prompt key label switches between keyboard ("Space") and gamepad ("X") based on the last input device.
- **Inventory system**:
  - `Inventory` autoload (`scripts/Inventory.gd`) holds `items: Array[InventoryItemData]` and emits `inventory_changed` on every mutation. `_ready()` currently seeds temporary test items (caguama, taco, machete, cinta). Capacity is `CAPACIDAD_BASE` (6) or the `capacidad` of the equipped `mochila` (doesn't take a slot); `add_item` returns false when full and `equipar_mochila` only accepts a bigger backpack (the old one is discarded). `combinar(index_a, index_b)` applies the first matching `RECETAS` entry (`scripts/RecetaData.gd`: `a`, `b`, `resultado`; `resources/recetas/*.tres`).
  - `InventoryItemData` (`scripts/InventoryItemData.gd`) is a `Resource` with name, description, icon, `inspection_model` (a PackedScene whose root must be `Node3D`) , `curacion` (life restored by Utilizar; 0 = not usable), `capacidad` (> 0 = it's a backpack) and `tinte` (alpha > 0 paints the whole model that colour, without its texture: the three backpacks in `resources/productos/mochila*.tres`, 8/10/14 slots, share `mochila.scn`). `crear_modelo(tamano)` returns the model centred and normalized inside a holder node (models come in any unit; long ones are turned sideways). Items are authored as `.tres` files in `resources/`.
  - `Salud` autoload (`scripts/Salud.gd`): `vida` (test value 60 of 100), `vida_max`, signal `cambio`, `estado()` text. Only the inventory changes it for now.
  - `scenes/InventoryUI.tscn` / `scripts/InventoryUI.gd` (instanced in `map_test.tscn`, layer 11, not in `world.tscn`): CanvasLayer with a NAVIGATING/INSPECTING/COMBINING state machine. Tab/Start (`inventory_toggle`) opens it and pauses the tree (it runs with `process_mode` Always), which is what stops `E`/arrows from also moving the player and camera; it won't open while the `jugador` is disabled or its physics stopped (shop, stall close-up, drone). Q/E or left/right cycle items, up/down choose among the commands that apply to the item (Examinar/Utilizar/Combinar), Enter confirms, Esc goes back one step and finally closes. Run alone, it stays open. The look is inspired by Silent Hill 2, not a copy (the user's request), and uses the game's default font and marker yellow: black screen, Estado = the paused game (the view grabbed on opening, cropped below the minimap, not tinted: it shows where the player is) with `Salud.estado()` as coloured text over it, Equipo = the backpack model and used/total count, and a row of up to 7 items (`RANURAS`, one model per item in `modelos`, placed by `_lugar`) going back into a black depth fog so they fade with distance. The full-screen 3D preview lives in a SubViewport (not rendered while closed) whose `PreviewWorld` node runs `InventoryInspectViewer.gd` (arrow-key rotation of the centre model, PageUp/PageDown or mouse-wheel zoom).
  - **Paper map**: M or gamepad Select (`inventory_map`) shows `scripts/MapaUI.gd` (state `MAPA`), from the open inventory or straight from the game (`InventoryUI._mapa_directo`: closing it then returns to the game, not the item list). Missing zones are drawn empty, so it opens with no pieces. Nothing else may bind physical M (the safehouse's +$100 is on P). `scripts/map/ZonasMapa.gd` holds 9 hand-drawn zones over `minimapa.png` with shared vertices, so they cover the map exactly. Each zone shows only once you have its piece: `PiezasMapa` autoload (not inventory items, survive fainting, cleared on restart), `scripts/map/PiezaMapa.gd` pickups placed by `Partida._lugares_de_piezas` in front of the interactive store nearest each zone's centre, or beside a lamp post. You start with your spawn zone's piece. `Partida` announces zones as you enter them. Zones are in real-map coordinates, so `Safehouse` sets `piezas_en_el_mapa` false and uses its own test pickup and U key.
  - `scripts/WorldItem.gd`: pickup in group `interactuable` that shows its normalized model and a prompt inside its Area3D; `interact()` equips it (`capacidad` > 0) or adds it to `Inventory` and frees itself, or stays on the ground if it doesn't fit (the prompt says so). `ObjetoPrueba1/2/3` and `MochilaPrueba1/2/3` in `map_test.tscn` are test pickups by the spawn.
- **Shaders** (`shaders/`): `ps1_combined.gdshader` merges the three standalone experiments (`jittershader` screen-space vertex snap, `vertex_wobble` view-space snap, `affine_warp` affine UVs) with per-effect toggles — prefer it for new materials.

## Real map and everything on it (`scenes/map_test.tscn`)

**Read `docs/mapa/tecnico.md` before changing the map pipeline, streaming, stores, houses, warehouses, walls, street lights, ground, deterioration, interiors, shop UI, or fruit machines.** It has the full detail, the regeneration commands and the reasons behind each decision. Keep it in sync with those systems. `docs/mapa/README.md` is the user-facing (Spanish) guide. Game design and open team decisions are in `docs/especificaciones.md`.

Overview:
- A real area of Zapopan built from OpenStreetMap with OSM2World by `tools/map_import/` (Python and Godot scripts), streamed from `resources/map/cuadros/`. `models/zona_mapa.glb` is gitignored; only rebuild it when changing the map.
- `scripts/map/`: `MapStreamer` (chunks), `MapPuntos` (stores), `MapCasas`, `MapBodegas`, `MapBardas`, `MapArboles`, `MapPasto`, `MapAlumbrado`, `MapDron` (V toggles the drone), `MapMinimapa`, `Maquinita`/`TragamonedasUI`/`Cohetes` (fruit machines). `scripts/tragamonedas.gd` is the machine's logic.
- `scripts/interiores/`: fixed first-person shop scenes, entered through the yellow arrows (`Interiores.gd`).
- `godot --path . tools/medir_mapa.tscn` measures FPS, frame times and draw calls at fixed spots (needs a window): run it before and after anything that might cost frames.
- New streaming systems must use the per-frame load budget in `scripts/map/CargaCuadro.gd`, and its `carga()`/`descarga()` so they load less on foot than in the drone. Don't add per-instance `StandardMaterial3D`s in builders: recompiling them caused stutter.
- Scripts in `tools/` run with `-s`, before autoloads exist. Anything they load, including `MapPuntos` and what it references, must not name `Cartera`, `Salud` or `Inventory` directly; use `load()` at runtime.
- Map data is ODbL; keep the attribution in `CREDITS.md`. Don't use Google Maps or Street View data for geometry.

## Danger: day/night, zombies, fighting, fainting (`map_test.tscn`)

- `scripts/map/Ciclo.gd` (`Ciclo` node): 12 min day + 8 min night, 30 s transitions, starting 60 s into the day; signals `aviso_atardecer` (1 min before), `anochecio`, `amanecio`. **N** jumps to the next dusk or dawn. It drives `Alumbrado.configurar_noche`, sun, ambient and fog. `locales_preview.tscn` still uses the instant `MapNocheDebug.gd`.
- `scripts/map/Zombis.gd` (`Zombis` node): places zombies 24-36 m from the player, on the street (downward ray, `ALTO_CALLE`) and out of camera, from a pool of 30 pre-built ones (`Zombie.despertar`/`dormir`, never `new`/`queue_free` except the boss). Loose ones: every 3 s, max 2 + `Deterioro.zona` × 8 + 1 per night after the first, capped at 12. Total cap 30. Removes those beyond 70 m; all collapse at dawn. Spawns stop while the player is frozen.
- `scripts/map/Director.gd`: L4D-style pacing, decides when zombies spawn. `intensidad` rises with damage and nearby kills and decays when nobody is attacking; states ARMANDO → SOSTENER → BAJANDO → RESPIRO. Mobs (`aparecer_turba`, `Zombie.cazador`: faster, always hunt the player) come every 90-180 s during ARMANDO. Timings come from secondary sources on Valve's talk; the numbers are for tuning by playing.
- `scripts/map/CampoFlujo.gd`: street pathing for zombies, a 48 m flow field filled breadth-first and asked of physics (layer 1) cell by cell with a per-frame budget. One to the player and one to the refuge entries. Barricades (layer 3) aren't obstacles, so paths lead up to them.
- `scripts/map/Zombie.gd`: `zombie_gordo` model, 30 life, 3-5 m/s. Follows `CampoFlujo` to its target, straight when close or outside the field, sidesteps when stuck, hits for 12, gives $1-3 when killed. Collision layer 2, mask 1 + 2 + 3, so zombies are solid to each other. `move_and_slide` alone still let them overlap, so `Zombis._no_encimar` separates pairs after everyone has moved (`process_physics_priority`, `Zombie.apartarse` collides with walls only). Near its target, a zombie blocked by another waits instead of sidestepping. Doesn't act while the player is frozen.
- **Melee feel**: each hit flashes the zombie white (`Zombie._pintar_blanco`), plays `whack`, blasts dirty water along the hit (`scripts/map/Liquido.gd`: drops simulated in GDScript, drawn by two shared MultiMeshes, starting inside the body, hanging during the freeze, stretching in flight and leaving splats on landing that fade after 15 s; caps of 256 drops and 60 splats; found through group `liquido`), knocks it back (`EMPUJON`) and bounces the player (`_retroceso`, added only around `move_and_slide` because braking overwrites `velocity`), shakes the camera (`h_offset`/`v_offset`) and freezes (`Player._congelar`). Force scales with weapon damage. One whack, shake and freeze per swing however many it hits. A player kill swells the zombie white during the freeze, then it bursts (`Zombie._reventar`): water, scraps, `reventar`, a shrinking puddle. Dawn deaths still fall. **Timing uses `Time.get_ticks_msec()` and the freeze is released by `Player.RelojCongelada`, a child that always processes: a `SceneTreeTimer` stayed stuck for seconds at this time scale, even with `ignore_time_scale`.** `Partida._ganar` waits `GANAR_ESPERA` so the boss's burst is seen before the pause. A burst leaves `scripts/map/RestosZombi.gd` (flat skin, rots after 6 s to a procedural skeleton, gone at 60 s, at most 16, shared meshes; separate from `Zombie` so pool slots aren't held).
- **Pixel-art accents** (`scripts/map/EfectosPixel.gd`, created by `Zombis`, found through group `efectos_pixel`): billboarded `Sprite3D` sheets from [pixelfx](https://github.com/patch-gg/pixelfx) (MIT, credited) on top of the 3D feel, never instead of it. Six slots, each with variants for the team to pick (AG's proposal): `golpe` (swing, `Player._golpear`, with a bare-hand sheet), `impacto` (`Zombie.recibir_golpe`, a different sheet on the kill), `herido` (`Player.recibir_dano`), `muerte` (`Zombie._reventar`), `amanecer` (a dawn body vanishing), `recoger` (`WorldItem`, `PiezaMapa`). F2-F7 cycle them in the safehouse; the choice is a `static var`, so it carries over to the map. Sheets run on game time, so they hold during the freeze, and start at the sheet's own hit time (`golpe_en`). A pool of 16, reused oldest first. **Sheets**: list in `tools/pixelfx/efectos.json` (pixelfx id, palette from the game's colours), rebuilt with `node tools/pixelfx/exportar.mjs <pixelfx checkout>` into `resources/fx/` (PNG + a trimmed JSON). Add `resources/fx/*.json` to the export filter. pixelfx effects drawn from its stock character's body (`disintegrate`, `soul-rise`, `dissolve-burn`, status effects) don't fit: they draw that character, not ours; trimmed copies live in `tools/pixelfx/fx/taquito/` (`haz`, `fuego-tambo`, `marca-rabia`), which `exportar.mjs` copies into the pixelfx checkout (run `node tools/check.mjs taquito/<name>` there after editing one). **Second round** (all off with F9 in the safehouse, `EfectosPixel.extras`): one-shot slots `tablas` (`EntradaRefugio.recibir_golpe`), `pisada`/`jefe` (boss steps every `JEFE_PASO` m; the slam when it first gets within `JEFE_ANUNCIA`, since it spawns off camera), `premio` (`Maquinita.mostrar_premio`), `curar` (`InventoryUI._utilizar`, plays once the inventory closes). **Loops** use `shaders/sprite_pixel.gdshader`, which picks the frame from `TIME` (no script per frame) with one shared material per sheet (`EfectosPixel.material_bucle`) and per-instance phase (instance uniform, or `INSTANCE_CUSTOM.r` on a MultiMesh); quads need a `custom_aabb` because the shader stretches them: tinaco jets (`Refugio._goteras`, one more at 3/4, 1/2, 1/4 life), beams over `PiezaMapa`/`BolsaMuerte`, the hunter mark (`Zombie._rabia`), and `MapAlumbrado`'s burning barrels (3D cylinder + fire, beside some posts once `Deterioro.zona` > `TAMBO_DESDE`, with collision) and sparks on flickering lamps in ruined zones, built per cell by static `armar_tambos`/`armar_chispas` (the safehouse demo uses the same). **Screen overlays** (`EfectosPixel.pantalla`, awaitable): `Supervivencia` plays `crt-off` when you faint (0-1 s, then black, then 1-2 s on waking; plain fades if extras are off) and dawn god rays (additive, on layer 7 under Supervivencia so they never show over the faint screen; bottom 22 px cropped because the sheet lights its own floor). Low life drips blood with `Liquido`, not a sheet. The god-ray sheet is rendered at 6 fps (`"fps"` in `efectos.json`): 1920×1800 instead of 4160×4320 at 30 fps.
- **Getting hit**: `Player.recibir_dano(dano, desde, empuja)` freezes, flashes the model white, shakes, pushes about 1.5 m away from the attacker (3 m from the boss), sprays blood the same way and emits `golpeado`, on which `Supervivencia` shows 2 frames of hard black and white (`shaders/impacto.gdshader`, 17 ms each on the real clock, `IMPACTO_ACTIVO`). All of this is limited by the 0.7 s invulnerability. `Supervivencia` always processes so the impact can't stick under the inventory.
- `Player`: `attack` action (left click, F, gamepad X) in a forward cone (`_golpear`). Damage is the best `InventoryItemData.dano` in the inventory (`Inventory.arma()`, machete 12, reinforced 18), or 5 bare-handed; nothing needs equipping, and the weapon shows in the hand (`Fist.R`). `player.gd` is loaded by `tools/` scripts through `MapPuntos`, so it reaches autoloads with `get_node("/root/...")`. Its timers tick in `_physics_process`, so they stop while it's frozen.
- `scripts/map/Supervivencia.gd`: no health bar (life shows in the inventory): red flash on damage, pulsing red edges below 35 %, dusk/night/dawn messages. At 0 life: inventory items drop in one recoverable `BolsaMuerte` (a new one replaces the old; money and backpack stay), fade, respawn at `punto_regreso` with 50 life, zombies within 20 m of it cleared.
- `scripts/map/Refugio.gd` + `EntradaRefugio.gd`: walled 14×14 m yard with one entry per side and the tinaco at its origin, in `map_test.tscn` at (203, 662). Tablas barricade entries on collision layer 3, which zombies have in their mask and the player doesn't. Zombies go for the player only within 12 m on the same side of the wall, otherwise the nearest entry, then the tinaco (`Zombie._destino`). Beyond `Zombis.LEJOS` no zombies exist there, so the attack is simulated (`ASEDIO`).
- `scripts/map/Partida.gd`: 3-night run. On the last night `Ciclo.retener_noche` holds dawn and the boss (`Zombie.es_jefe`) spawns once the player is near; killing it wins, losing the tinaco loses. Restart calls `reiniciar()` on `Inventory`, `Salud` and `Cartera`. This is AG's working proposal; spec §1.2, §1.3 and §1.5 votes are still open.
- At night shops, stalls and machines close and kick you out (`Interiores._echar`, `TragamonedasUI._echar`), and the drone too where `MapDron.cerrado_de_noche` is set (`map_test.tscn` only). They find the clock through group `ciclo`.
- `scripts/Sonidos.gd`: all generated sounds. A node re-enables `_physics_process` when it becomes ready if the script defines it: call `set_physics_process(false)` after `add_child`.
- `map_test.tscn` sets the player to 10/18 m/s for walking the map, which outruns every zombie.

## Missions

`Misiones` autoload (`scripts/Misiones.gd`): one active at a time, each once per day; it fails at nightfall or when its timer ends, and can be retried the next day. Offers stop at the dusk warning. `scripts/map/MisionesMundo.gd`, created by `Partida`, holds what's in the world: givers (`npc.tscn` using `al_hablar`, a callable returning the line for each press), the objective arrow, delivery spots, the dog (`CosaMision.gd`), the objective line, and the minimap and paper-map targets. **To add a mission without code:** copy a `.tres` in `resources/misiones/` (`MisionData` with `PasoMision` steps: `TENER_OBJETOS`, `ENTREGAR`, `VISITAR`, `RECOGER`) and add it to `Misiones.ARCHIVOS`. Each needs a giver spot, and a new `lugar` keyword or step type needs code in `MisionesMundo`. `Player.cargar`/`soltar_carga` show something held, with `Walk_Carry`. Stepping onto a store's yellow arrow enters the store, so tests must stand beside it.

## Character (`scripts/Personaje.gd`)

`Personaje` autoload: name, skin tone, build, height, head and clothes, saved in `user://personaje.cfg` and kept on restart. Every number and line is at the top of that script. `scripts/CreadorPersonaje.gd` is the screen, opened after Jugar (`Inicio._crear_personaje`) and by C in the safehouse. **Skin tone only changes how the world treats you**: `Interior._factor` (peso prices, not water), `Misiones._completar` (pesos, not items) and `Personaje.linea` (shop, givers, neighbours). Combat, zombie drops and fruit machines must stay out of it: that's the joke, and a darker character is never weaker. Build and height change life, speed, damage and reach in `Player.aplicar_personaje`, on top of the scene's own values. `Personaje.vestir` recolours one model's own copies of the `Skin` and `Main` materials, and `scripts/CuerpoPersonaje.gd` (`SkeletonModifier3D`) scales bones after the animation; the collision capsule stays the same. This is AG's proposal; the team hasn't voted on it (spec §10.2).

## People (`scripts/map/Gente.gd`)

By day only: at dusk (`aviso_atardecer`) they hurry and no more appear, at night nobody's there, and they return at dawn. Up to 12 walkers on `resources/map/banquetas_mapa.json` (from OSM, `godot --path . --headless -s tools/map_import/banquetas.gd`), including a blue garrafonero with a jug. Walkers use the tinted ninja because it's the only human model with a walk cycle (spec §10.2: retargeting is still pending). ## Dev safehouse (`scenes/safehouse.tscn`, `scripts/map/Safehouse.gd`)

`godot --path . scenes/safehouse.tscn`: a walled 100 m yard for testing without walking the map, using the real systems, not copies. **When you add a mechanic, add it here too.** `MapPuntos` builds one business of each giro from `user://puntos_safehouse.json` (written in `_enter_tree`; `NEGOCIOS` is the list) with the real `Interiores`; three `Maquinita`s, one per `Estado`; a `WorldItem` for everything in `resources/productos/` (new `.tres` appear on their own); Urbi houses, `Ciclo`, `Zombis`, `Supervivencia`, `Refugio`, `Partida`, `Gente` (its sidewalk is `BANQUETAS`), `InventoryUI`, drone and an NPC. Its keys are on screen (`PANEL_TEXTO`) and only work while the player is free. It starts with $500 and thinner fog than the map. No minimap, streets or warehouses: F10 goes to `map_test.tscn` for those.

## Conventions / gotchas

- **PS1 vertex snapping is only for characters and props.** World shaders `#define PS1_MUNDO` before including `ps1_vertex.gdshaderinc`, which skips it; world materials on `ps1_combined` set `jitter_enabled` and `wobble_enabled` false; `MapStreamer._quitar_brinco` does it for the baked chunk materials. Pieces stuck to each other (paint, trim, graffiti) jumped against each other otherwise.
- `Player._process` smooths only the visible model and camera between the last two physics positions (`Engine.get_physics_interpolation_fraction`), because the body moves 60 times a second and the screen more often. Project-wide physics interpolation is off. `godot --path . tools/medir_mapa.tscn -- --movimiento` measures it (`--sin-suavizar` to compare).
- `ps1_suelo` floors overlap at the same height in the baked map, so each type gets a depth layer (`SueloPasto.capa`, set by `MapStreamer._quitar_brinco`): asphalt, cobbles, sidewalk, grass, dirt.
- After adding a `class_name`, run `godot --path . --headless --import` once, or headless runs won't find the class. A headless run with a parse error sits idle forever, so give test runs a time limit.

- PS1 shaders must write `POSITION` unconditionally (`ps1_vertex()` returns the unsnapped clip position when `jitter_enabled` is false). A spatial shader that writes `POSITION` only inside an `if` leaves the mesh invisible when the branch isn't taken. The original `ps1_combined` had this bug; `shaders/jittershader.gdshader` still does. Huge meshes (the 1900 m `Suelo`) need jitter/wobble off, otherwise vertex snapping distorts them near the camera.
- `pkill -f <pattern>` from the Bash tool also kills the tool's own shell when the pattern appears in the command line; use a pattern that can't match itself (e.g. `fetch_sat[e]lite`).
- Chunk `visibility_range_end` is 250 m plus half the chunk's AABB diagonal, because Godot measures it to the AABB center and some chunks are 800+ m wide.
- Input actions are defined in `project.godot` (`move_*`, `camera_*`, `jump`, `sprint`, `inspect_*`, `inventory_*`). Note `E` is bound to both `camera_right` and `inventory_next`, and arrow keys to `move_*`, `inspect_*` and (left/right) `inventory_next`/`inventory_previous`. These only coexist because the open inventory pauses the tree; don't open a menu using them without pausing.
- Resources are referenced by `uid://`; keep each `.gd.uid` file alongside its script when moving/renaming, or edit via the Godot editor.
- `scenes/world.tscn` and `scripts/Inventory.gd.uid` are listed in `.gitignore` but are already tracked, so changes to them still show up in git.
- `scenes/InventoryUI.tscn*.tmp` files are editor save leftovers, not real scenes.
