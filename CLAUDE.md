# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Guadalajaja" — a Godot 4.7 (Forward Plus, Jolt Physics) third-person 3D prototype with a PS1-style look. All gameplay code is GDScript; there is no build system, linter or test suite. Code comments and in-game UI text are in (informal) Spanish — keep new player-facing strings in Spanish.

## Commands

Godot 4.7 is installed as `godot`.

```bash
godot --path . --editor            # open in the editor
godot --path .                     # run the main scene (scenes/inicio.tscn, the start screen)
godot --path . scenes/InventoryUI.tscn   # run a single scene in isolation
godot --path . --headless --import # (re)import assets / regenerate .godot cache
godot --path . --headless --check-only --script res://scripts/player.gd  # parse-check one script
```

## Architecture

- **Main scene**: `scenes/inicio.tscn` (`scripts/Inicio.gd`): the start screen, a small night scene built in code with the menu over it. Jugar opens the character creator, then loads `scenes/map_test.tscn` in a thread with "Cargando..." on screen; Créditos reads `CREDITS.md` at runtime (add it to the export filter when exporting; the required map attributions are the fallback).
- **Old prototype**: `scenes/world.tscn` is no longer what opens, but still runs by path. It instances `player.tscn`, two `npc.tscn` instances (configured per-instance via exported `tint` and `dialogue`), level geometry from `models/*.glb`, and a `PS1_Postprocess` CanvasLayer whose full-screen ColorRect runs `shaders/dittershader.gdshader` over the screen texture. Render resolution is 640×480 with `viewport` stretch mode and nearest texture filtering — this is intentional for the retro look.
- **Player** (`scripts/player.gd`, `class_name Player`): CharacterBody3D. Movement is camera-relative (`CameraPivot` yaw + `SpringArm3D` pitch); the visual body is the child `Frijol`, which is rotated toward the movement direction separately from the physics body. The `jump` action doubles as "interact": if any node in the `npc` or `interactuable` groups reports `is_player_inside()`, the nearest one gets `interact()` instead of jumping. The player is in group `jugador`. Q/E no longer turn the camera: Q is the `curarse` action (`Player._curarse`: eats the item from `Inventory.mejor_curacion` through `Inventory.usar_curacion`, the same path as the inventory's Utilizar, and locks you for `CURAR_DURA`), E joins R on `cambiar_arma`. Both are also `inventory_previous`/`inventory_next`, which only works because the open inventory pauses the tree. Animation is delegated to `Frijol/Ninja` via duck-typed `update_animation(is_moving, is_airborne, is_sprinting)` (`scripts/character_animation.gd`).
- **Animation clips** are looked up by suffix (`"Idle"` matches `"...|Idle"`) because the imported FBX (`models/ninja_male.fbx`) prefixes clip names; loop mode is forced in code. Both player and NPC share this model.
- **NPC** (`scripts/npc.gd`): registers itself in group `npc`; a `TalkArea` Area3D detects the `Player`. The interaction prompt and speech bubble are 2D UIs rendered into SubViewports and displayed on `Sprite3D`s. The prompt key label switches between keyboard ("Space") and gamepad ("X") based on the last input device.
- **Inventory system**:
  - `Inventory` autoload (`scripts/Inventory.gd`) holds `items: Array[InventoryItemData]` and emits `inventory_changed` on every mutation. `_ready()` currently seeds temporary test items (caguama, taco, machete, cinta). Capacity is `CAPACIDAD_BASE` (6) or the `capacidad` of the equipped `mochila` (doesn't take a slot); `add_item` returns false when full and `equipar_mochila` only accepts a bigger backpack (the old one is discarded). `combinar(index_a, index_b)` applies the first matching `RECETAS` entry (`scripts/RecetaData.gd`: `a`, `b`, `resultado`; `resources/recetas/*.tres`).
  - `InventoryItemData` (`scripts/InventoryItemData.gd`) is a `Resource` with name, description, icon, `inspection_model` (a PackedScene whose root must be `Node3D`) , `curacion` (life restored by Utilizar; 0 = not usable), `capacidad` (> 0 = it's a backpack) and `tinte` (alpha > 0 paints the whole model that colour, without its texture: the three backpacks in `resources/productos/mochila*.tres`, 8/10/14 slots, share `mochila.scn`). `crear_modelo(tamano)` returns the model centred and normalized inside a holder node (models come in any unit; long ones are turned sideways). Items are authored as `.tres` files in `resources/`.
  - `Salud` autoload (`scripts/Salud.gd`): `vida` (test value 60 of 100), `vida_max`, signal `cambio`, `estado()` text. Only the inventory changes it for now.
  - `scenes/InventoryUI.tscn` / `scripts/InventoryUI.gd` (instanced in `map_test.tscn`, layer 11, not in `world.tscn`): CanvasLayer with a NAVIGATING/INSPECTING/COMBINING state machine. Tab/Start (`inventory_toggle`) opens it and pauses the tree (it runs with `process_mode` Always), which is what stops `E`/arrows from also moving the player and camera; it won't open while the `jugador` is disabled or its physics stopped (shop, stall close-up, drone). Q/E or left/right cycle items, up/down choose among the commands that apply to the item (Examinar/Utilizar/Combinar), Enter confirms, Esc goes back one step and finally closes. Run alone, it stays open. The look is inspired by Silent Hill 2, not a copy (the user's request), and uses the game's default font and marker yellow: black screen, Estado = the paused game (the view grabbed on opening, cropped below the minimap, not tinted: it shows where the player is) with `Salud.estado()` as coloured text over it, Equipo = the backpack model and used/total count, and a row of up to 7 items (`RANURAS`, one model per item in `modelos`, placed by `_lugar`) going back into a black depth fog so they fade with distance. The full-screen 3D preview lives in a SubViewport (not rendered while closed) whose `PreviewWorld` node runs `InventoryInspectViewer.gd` (arrow-key rotation of the centre model, PageUp/PageDown or mouse-wheel zoom).
  - **Paper map**: M or gamepad Select (`inventory_map`) shows `scripts/MapaUI.gd` (state `MAPA`), from the open inventory or straight from the game (`InventoryUI._mapa_directo`: closing it then returns to the game, not the item list). Missing zones are drawn empty, so it opens with no pieces. Nothing else may bind physical M (the safehouse's +$100 is on P), except where `InventoryUI.con_mapa` is false (the tinaco defence uses it for the music). `scripts/map/ZonasMapa.gd` holds 9 hand-drawn zones over `minimapa.png` with shared vertices, so they cover the map exactly. Each zone shows only once you have its piece: `PiezasMapa` autoload (not inventory items, survive fainting, cleared on restart), `scripts/map/PiezaMapa.gd` pickups placed by `Partida._lugares_de_piezas` in front of the interactive store nearest each zone's centre, or beside a lamp post. You start with your spawn zone's piece. `Partida` announces zones as you enter them. Zones are in real-map coordinates, so `Safehouse` sets `piezas_en_el_mapa` false and uses its own test pickup and U key.
  - `scripts/WorldItem.gd`: pickup in group `interactuable` that shows its normalized model and a prompt inside its Area3D; `interact()` equips it (`capacidad` > 0) or adds it to `Inventory` and frees itself, or stays on the ground if it doesn't fit (the prompt says so). `ObjetoPrueba1/2/3` and `MochilaPrueba1/2/3` in `map_test.tscn` are test pickups by the spawn.
- **Shaders** (`shaders/`): `ps1_combined.gdshader` merges the three standalone experiments (`jittershader` screen-space vertex snap, `vertex_wobble` view-space snap, `affine_warp` affine UVs) with per-effect toggles — prefer it for new materials.

## Danger: day/night, zombies, fighting, fainting (`map_test.tscn`)

- `scripts/map/Ciclo.gd` (`Ciclo` node): 12 min day + 8 min night, 30 s transitions, starting 60 s into the day; signals `aviso_atardecer` (1 min before), `anochecio`, `amanecio`. **N** jumps to the next dusk or dawn. It drives `Alumbrado.configurar_noche`, sun, ambient and fog. `locales_preview.tscn` still uses the instant `MapNocheDebug.gd`.
- `scripts/map/Zombis.gd` (`Zombis` node): places zombies 24-36 m from the player, on the street (downward ray, `ALTO_CALLE`) and out of camera, from a pool of `max_total` (30) pre-built ones (`Zombie.despertar`/`dormir`, never `new`/`queue_free` except the boss). Loose ones: every 3 s, max 2 + `Deterioro.zona` × 8 + 1 per night after the first, capped at 12. Total cap 30. Removes those beyond 70 m; all collapse at dawn. Spawns stop while the player is frozen.
- `scripts/map/Director.gd`: L4D-style pacing, decides when zombies spawn. `intensidad` rises with damage and nearby kills and decays when nobody is attacking; states ARMANDO → SOSTENER → BAJANDO → RESPIRO. Mobs (`aparecer_turba`, `Zombie.cazador`: faster, always hunt the player) come every 90-180 s during ARMANDO. Timings come from secondary sources on Valve's talk; the numbers are for tuning by playing.
- `scripts/map/CampoFlujo.gd`: street pathing for zombies, a 48 m flow field filled breadth-first and asked of physics (layer 1) cell by cell with a per-frame budget. A cell is blocked if its box query **or** one of four rays across it (`_cruza_pared`, back faces on) hits: the baked chunks' hollow `ConcavePolygonShape3D` buildings were only half seen by the box, so the field led zombies into a wedge between one and the barricade. One to the player and one to the refuge entries. Barricades (layer 3) aren't obstacles, so paths lead up to them.
- `scripts/map/Zombie.gd`: `zombie_gordo` model, 30 life, 3-5 m/s. Follows `CampoFlujo` to its target, straight when close or outside the field, sidesteps when stuck, hits for 12, gives $1-3 when killed. A life bar floats above it (`shaders/barra_vida.gdshader`, billboard, one shared material, life as an instance uniform, hidden past `BARRA_HASTA` 35 m and on death). Collision layer 2, mask 1 + 2 + 3, so zombies are solid to each other. `move_and_slide` alone still let them overlap, so `Zombis._no_encimar` separates pairs after everyone has moved (`process_physics_priority`, `Zombie.apartarse` collides with walls only). Near its target, a zombie blocked by another waits instead of sidestepping. Doesn't act while the player is frozen.
- **Melee feel**: each hit flashes the zombie white (`Zombie._pintar_blanco`), plays `whack`, blasts dirty water along the hit (`scripts/map/Liquido.gd`: drops simulated in GDScript, drawn by two shared MultiMeshes, starting inside the body, hanging during the freeze, stretching in flight and leaving splats on landing that fade after 15 s; caps of 256 drops and 60 splats; found through group `liquido`), doesn't knock it back (`Zombie.EMPUJON` 0: Alan asked for ~0.5 m, but it pushed zombies out of reach and the combo missed its second hit, so JJ removed it; if raised, it goes into `_retroceso`, added to `velocity` in any live state and braked by `EMPUJON_FRENA`) and never stuns it: `Zombie.ATURDIR` is false because stunned zombies almost never hit JJ (8th defence test). With it true, melee stuns on `ATURDE_PROB` 20 % even while walking, plus the timed-hit window below. The pistol passes `cuerpo_a_cuerpo` false to `recibir_golpe`, so it neither pushes nor stuns. The boss's `JEFE_ARRASTRE` is still 0 and it's never stunned. **Timed hits** (`Player.pelea_a_tiempo`, toggled with 9 in the safehouse): a zombie starting an attack growls (no red tint: JJ didn't want it; the growl and the animation are the tell), and for `Zombie.CORTE` (0.3 s) a hit in that window stuns it (`HERIDO_DURA`) only while `ATURDIR` is on; otherwise the growl is just the cue to step away. You're only locked until your hit lands (`ATAQUE_QUIETO_A_TIEMPO`); moving after that releases the arm from where it is (`Barrido.soltar`) and resets the combo. Off, it's the previous test: never stunned, locked for the whole sweep and would bounce the player (`_retroceso`, added only around `move_and_slide` because braking overwrites `velocity`; `RETROCESO` is 0 at JJ's request, the getting-hit push below still uses it), shakes the camera (`h_offset`/`v_offset`) and freezes (`Player._congelar`, which restores the previous `Engine.time_scale`, not 1, so a sped-up test night survives hits). Force scales with weapon damage. One whack, shake and freeze per swing however many it hits. A player kill swells the zombie white during the freeze, then it bursts (`Zombie._reventar`): water, scraps, `reventar`, a shrinking puddle. Dawn deaths still fall. **Timing uses `Time.get_ticks_msec()` and the freeze is released by `Player.RelojCongelada`, a child that always processes: a `SceneTreeTimer` stayed stuck for seconds at this time scale, even with `ignore_time_scale`.** `Partida._ganar` waits `GANAR_ESPERA` so the boss's burst is seen before the pause. A burst leaves `scripts/map/RestosZombi.gd` (flat skin, rots after 6 s to a procedural skeleton, gone at 60 s, at most 16, shared meshes; separate from `Zombie` so pool slots aren't held).
- **Pixel-art accents** (`scripts/map/EfectosPixel.gd`, created by `Zombis`, found through group `efectos_pixel`): billboarded `Sprite3D` sheets from [pixelfx](https://github.com/patch-gg/pixelfx) (MIT, credited) on top of the 3D feel, never instead of it. Six slots, each with variants for the team to pick (AG's proposal): `golpe` (swing, `Player._golpear`, with a bare-hand sheet), `impacto` (`Zombie.recibir_golpe`, a different sheet on the kill; defaults to C, the dry hit with the crit on the kill, JJ's vote), `herido` (`Player.recibir_dano`), `muerte` (`Zombie._reventar`), `amanecer` (a dawn body vanishing), `recoger` (`WorldItem`, `PiezaMapa`). F2-F7 cycle them in the safehouse; the choice is a `static var`, so it carries over to the map. `golpe` defaults to no sheet (`EfectosPixel.PREDETERMINADA`): the swing leaves a 3D trail instead (`scripts/EstelaBarrido.gd`, JJ's pick), a solid crescent from part-way down the arm (its inner edge 0.3 m lower, or from behind it was edge-on) to the weapon tip, in stepped bands of the sweep sheet's palette and thinning as it ages, with white pixel dust puffs (billboard quads, instance uniforms `edad`/`semilla`) every few pieces, that `Barrido.gd` samples along the arc, so it follows where the character faces from any angle. F2 still brings back the sheets, which run right to left (`Player.BARRE_AL_FRENTE`) at arm height (`BARRE_ALTO`). Sheets run on game time, so they hold during the freeze, and start at the sheet's own hit time (`golpe_en`). A pool of 16, reused oldest first. **Sheets**: list in `tools/pixelfx/efectos.json` (pixelfx id, palette from the game's colours), rebuilt with `node tools/pixelfx/exportar.mjs <pixelfx checkout>` into `resources/fx/` (PNG + a trimmed JSON). Add `resources/fx/*.json` to the export filter. pixelfx effects drawn from its stock character's body (`disintegrate`, `soul-rise`, `dissolve-burn`, status effects) don't fit: they draw that character, not ours; trimmed copies live in `tools/pixelfx/fx/taquito/` (`haz`, `fuego-tambo`, `marca-rabia`), which `exportar.mjs` copies into the pixelfx checkout (run `node tools/check.mjs taquito/<name>` there after editing one). **Second round** (all off with F9 in the safehouse, `EfectosPixel.extras`): one-shot slots `tablas` (`EntradaRefugio.recibir_golpe`), `pisada`/`jefe` (boss steps every `JEFE_PASO` m; the slam when it first gets within `JEFE_ANUNCIA`, since it spawns off camera), `premio` (`Maquinita.mostrar_premio`), `curar` (`InventoryUI._utilizar`, plays once the inventory closes). **Loops** use `shaders/sprite_pixel.gdshader`, which picks the frame from `TIME` (no script per frame) with one shared material per sheet (`EfectosPixel.material_bucle`) and per-instance phase (instance uniform, or `INSTANCE_CUSTOM.r` on a MultiMesh); quads need a `custom_aabb` because the shader stretches them: tinaco jets (`Refugio._goteras`, one more at 3/4, 1/2, 1/4 life), beams over `PiezaMapa`/`BolsaMuerte`, the hunter mark (`Zombie._rabia`), and `MapAlumbrado`'s burning barrels (3D cylinder + fire, beside some posts once `Deterioro.zona` > `TAMBO_DESDE`, with collision) and sparks on flickering lamps in ruined zones, built per cell by static `armar_tambos`/`armar_chispas` (the safehouse demo uses the same). **Screen overlays** (`EfectosPixel.pantalla`, awaitable): `Supervivencia` plays `crt-off` when you faint (0-1 s, then black, then 1-2 s on waking; plain fades if extras are off) and dawn god rays (additive, on layer 7 under Supervivencia so they never show over the faint screen; bottom 22 px cropped because the sheet lights its own floor). Low life drips blood with `Liquido`, not a sheet. The god-ray sheet is rendered at 6 fps (`"fps"` in `efectos.json`): 1920×1800 instead of 4160×4320 at 30 fps.
- **Getting hit**: `Player.recibir_dano(dano, desde, empuja)` freezes, flashes the model white, shakes, pushes about 1.5 m away from the attacker (3 m from the boss), sprays blood the same way and emits `golpeado`, on which `Supervivencia` shows 2 frames of hard black and white (`shaders/impacto.gdshader`, 17 ms each on the real clock, `IMPACTO_ACTIVO`). All of this is limited by the 0.7 s invulnerability. `Supervivencia` always processes so the impact can't stick under the inventory.
- `Player`: `attack` action (left click, F, gamepad X, only while the mouse is captured; with it freed by Esc, a left click recaptures it without attacking) in a forward cone (`_golpear`), hitting only the nearest live zombie (`ATAQUE_MAXIMO` 1): in a packed group one combo used to kill 5. Damage is the best `InventoryItemData.dano` in the inventory (`Inventory.arma()`, machete 12, reinforced 18), or 5 bare-handed; nothing needs equipping, and the weapon shows in the hand (`Fist.R`), `ARMA_TAMANO` 0.95 m long (0.6 read as a knife). `Personaje.vestir` only swaps the ninja's own body mesh for the hoodless one: it used to swap every mesh under the model, the weapon included. `player.gd` is loaded by `tools/` scripts through `MapPuntos`, so it reaches autoloads with `get_node("/root/...")`. Its timers tick in `_physics_process`, so they stop while it's frozen. The model only has `Punch` (a forward thrust), so `scripts/Barrido.gd` (a `SkeletonModifier3D` on the ninja's skeleton, like `CuerpoPersonaje`, started by `_atacar`) overrides it with a diagonal slash: the right arm (`UpperArm.R`→`Fist.R`) straightened from high back-right (`ALTO_INICIO`) to low front-left (`ALTO_FIN`), passing the front at head height at `ATAQUE_PEGA_EN`, with the `Torso` turning and leaning along; the return swing comes down the other way, so two hits draw an X. Hits chain endlessly, each one the other way (`Barrido.golpe(lado)`, `Player._lado_golpe`): the next can start at `COMBO_DESDE` (end of the sweep) without waiting for the cooldown, from where the arm is (no return to the body, no new `Punch`); one earlier press per swing is buffered (`_golpe_guardado`). After the cooldown it still alternates within `COMBO_VENTANA`, otherwise it starts over right to left. You can't walk while attacking (see timed hits for how long). Its timings and angles are at the top of the script.
- **Pistol** (`scripts/Pistola.gd`, a child of `Player`; JJ's test in `golpe-direccion`): the `cambiar_arma` action (R or E, gamepad RB) switches between it and the melee weapon, and `attack` then shoots instead of swinging.
  - It aims at the centre of the screen (option A of spec §1.4, still open).
  - The ray is on layers 1 + 2 and excludes the player, so walls and barricades are cover.
  - If the centre misses, the live zombie nearest the crosshair within `AYUDA` 2.5° that can be seen gets the shot.
  - It hits through `Zombie.recibir_golpe` (8 damage × `_factor_dano`, 4 shots per zombie against the machete's 3 hits, JJ's numbers: it wears the group down while it approaches; no knockback or stun), with no freeze (rapid fire stalled with it), only a short camera shake.
  - Magazine of 12 with an automatic 1.5 s reload and endless ammo.
  - The weapon/ammo text also shows `Q curar (n)` (`Inventory.curaciones()`).
  - Shot visuals: a yellow tracer from the muzzle (`Player.canon()`, a `Marker3D` at `PISTOLA_CANON` on the model) and a muzzle light for 50 ms, plus the generated `disparo`/`recarga` sounds.
  - **Fortnite-style camera** (`Player._camara_al_hombro`, real clock, so the hit freeze doesn't leave it halfway): with the pistol the camera goes over the right shoulder (`HOMBRO` via `h_offset`, added in `_sacudir`), higher (`HOMBRO_ALTO`, above the big-headed ninja) and closer (`HOMBRO_BRAZO`), and the model always faces the camera's direction while you strafe. The centred character covered the crosshair.
  - The `apuntar` action (right click, gamepad LT) zooms (`APUNTA_FOV`, `APUNTA_BRAZO`, `APUNTA_HOMBRO`), slows walking (`APUNTA_VELOCIDAD`, no sprint) and the mouse (`APUNTA_RATON`).
  - The model is `pistola_mk23`, shown in the hand through `_mostrar_arma`, normalized by an in-memory `InventoryItemData`; it's not an inventory item yet. Its barrel is the model's -X and the grip is at +X, so it's `PISTOLA_TAMANO` 0.55 m (0.3 vanished in the big fist), turned by `PISTOLA_GIRO` plus `PISTOLA_ROLL` 180 (without it the grip points up) and shifted by `PISTOLA_MANGO` so the grip sits in the fist.
  - **Holding and aiming poses** (`scripts/PoseArma.gd`, a `SkeletonModifier3D` beside `Barrido`, fed each frame by `Player._posar`): the ninja has no pistol clips and Quaternius's are on another skeleton (retarget pending, spec §10.2), so the arms and torso are posed on the bones over the animation, and the legs keep walking. Holding: right elbow down, gun forward and low. Aiming (`apuntar`, or `ARRIBA_TRAS_TIRO` 0.8 s after a hip shot, `Player.pose_tiro`): both arms straight at the crosshair point (`MIRA_LEJOS` along the camera ray, so it follows pitch), the left hand reaching the right with a two-bone solve (`_codo`), the torso turned and tilted with the aim, and a recoil kick per shot. The ninja's skeleton is tiny and scaled: metre offsets are divided by its scale. Weight 0 without the pistol or while the player is stopped.

- `scripts/map/Supervivencia.gd`: a life bar top left (under the faint's black), red flash on damage, pulsing red edges below 35 %, dusk/night/dawn messages. - `scripts/map/Refugio.gd` + `EntradaRefugio.gd`: walled 14×14 m yard with one entry per side and the tinaco at its origin, in `map_test.tscn` at (203, 662). ## Conventions / gotchas

- **PS1 vertex snapping is only for characters and props.** World shaders `#define PS1_MUNDO` before including `ps1_vertex.gdshaderinc`, which skips it; world materials on `ps1_combined` set `jitter_enabled` and `wobble_enabled` false; `MapStreamer._quitar_brinco` does it for the baked chunk materials. Pieces stuck to each other (paint, trim, graffiti) jumped against each other otherwise.
- `Player._process` smooths only the visible model and camera between the last two physics positions (`Engine.get_physics_interpolation_fraction`), because the body moves 60 times a second and the screen more often. Project-wide physics interpolation is off. `godot --path . tools/medir_mapa.tscn -- --movimiento` measures it (`--sin-suavizar` to compare).
- `ps1_suelo` floors overlap at the same height in the baked map, so each type gets a depth layer (`SueloPasto.capa`, set by `MapStreamer._quitar_brinco`): asphalt, cobbles, sidewalk, grass, dirt.
- After adding a `class_name`, run `godot --path . --headless --import` once, or headless runs won't find the class. A headless run with a parse error sits idle forever, so give test runs a time limit.

- PS1 shaders must write `POSITION` unconditionally (`ps1_vertex()` returns the unsnapped clip position when `jitter_enabled` is false). A spatial shader that writes `POSITION` only inside an `if` leaves the mesh invisible when the branch isn't taken. The original `ps1_combined` had this bug; `shaders/jittershader.gdshader` still does. Huge meshes (the 1900 m `Suelo`) need jitter/wobble off, otherwise vertex snapping distorts them near the camera.
- `pkill -f <pattern>` from the Bash tool also kills the tool's own shell when the pattern appears in the command line; use a pattern that can't match itself (e.g. `fetch_sat[e]lite`).
- Chunk `visibility_range_end` is 250 m plus half the chunk's AABB diagonal, because Godot measures it to the AABB center and some chunks are 800+ m wide.
- Input actions are defined in `project.godot` (`move_*`, `camera_*`, `jump`, `sprint`, `inspect_*`, `inventory_*`). Note Q/E are bound to both `curarse`/`cambiar_arma` and `inventory_previous`/`inventory_next`, and arrow keys to `move_*`, `inspect_*` and (left/right) `inventory_next`/`inventory_previous`. These only coexist because the open inventory pauses the tree; don't open a menu using them without pausing.
- Resources are referenced by `uid://`; keep each `.gd.uid` file alongside its script when moving/renaming, or edit via the Godot editor.
- `scenes/world.tscn` and `scripts/Inventory.gd.uid` are listed in `.gitignore` but are already tracked, so changes to them still show up in git.
- `scenes/InventoryUI.tscn*.tmp` files are editor save leftovers, not real scenes.

## graphify (narrative graph)

`docs/graphify-out/` holds a knowledge graph of the six narrative docs (`lore`, `personajes`, `misiones`, `items`, `especificaciones`, `revision-historia`): 367 nodes, 12 communities, built by `/graphify` (the skill is in `.claude/skills/graphify/`). There is no graph of the code. Install with `uv tool install graphifyy`.

- For a story question, ask the graph before reading a whole doc, from the repo root: `graphify query "<question>" --graph docs/graphify-out/graph.json`; `graphify explain "<node>"` and `graphify path "<A>" "<B>" --undirected` take the same `--graph`. Then read only the sections it names (each node carries its doc and heading). Every narrative skill, `/game-quest`, `/game-lore` and the `narrative-writer` agent say this in their adaptation block; keep it in any new one.
- `docs/graphify-out/graph.html` is the browsable view and `GRAPH_REPORT.md` the summary (hubs, communities, loose ends).
- The graph is a snapshot: when it disagrees with a doc, the doc wins. After editing a narrative doc, rebuild with `/graphify docs --update` (re-extracts only changed files; `graphify update` is AST-only and does not reread docs). Run it from `docs/`, so the output stays in `docs/graphify-out/`. Cross-doc node ids were reconciled by hand on the first build (accents, full character names; lore's copies of characters merged into `personajes_*`), so check for dangling edges after an update.
- `.graphify_python` and `.graphify_root` are per-machine and gitignored. A rebuilt `graph.json` is rewritten whole, so a large diff to it is expected.
