# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Guadalajaja" — a Godot 4.7 (Forward Plus, Jolt Physics) third-person 3D prototype with a PS1-style look. All gameplay code is GDScript; there is no build system, linter or test suite. Code comments and in-game UI text are in (informal) Spanish — keep new player-facing strings in Spanish.

## Commands

Godot 4.7 is installed as `godot`.

```bash
godot --path . --editor            # open in the editor
godot --path .                     # run the main scene (scenes/world.tscn)
godot --path . scenes/InventoryUI.tscn   # run a single scene in isolation
godot --path . --headless --import # (re)import assets / regenerate .godot cache
godot --path . --headless --check-only --script res://scripts/player.gd  # parse-check one script
```

## Architecture

- **Main scene**: `scenes/world.tscn` (referenced by UID `uid://c2iut07k626j5` in `project.godot`). It instances `player.tscn`, two `npc.tscn` instances (configured per-instance via exported `tint` and `dialogue`), level geometry from `models/*.glb`, and a `PS1_Postprocess` CanvasLayer whose full-screen ColorRect runs `shaders/dittershader.gdshader` over the screen texture. Render resolution is 640×480 with `viewport` stretch mode and nearest texture filtering — this is intentional for the retro look.
- **Player** (`scripts/player.gd`, `class_name Player`): CharacterBody3D. Movement is camera-relative (`CameraPivot` yaw + `SpringArm3D` pitch); the visual body is the child `Frijol`, which is rotated toward the movement direction separately from the physics body. The `jump` action doubles as "interact": if any node in the `npc` group reports `is_player_inside()`, the nearest one gets `interact()` instead of jumping. `girar_con_qe` (on only in `map_test.tscn`) turns the camera with physical Q/E; it isn't an input action because Q is `inventory_previous` in `world.tscn`. Animation is delegated to `Frijol/Ninja` via duck-typed `update_animation(is_moving, is_airborne, is_sprinting)` (`scripts/character_animation.gd`).
- **Animation clips** are looked up by suffix (`"Idle"` matches `"...|Idle"`) because the imported FBX (`models/ninja_male.fbx`) prefixes clip names; loop mode is forced in code. Both player and NPC share this model.
- **NPC** (`scripts/npc.gd`): registers itself in group `npc`; a `TalkArea` Area3D detects the `Player`. The interaction prompt and speech bubble are 2D UIs rendered into SubViewports and displayed on `Sprite3D`s. The prompt key label switches between keyboard ("Space") and gamepad ("X") based on the last input device.
- **Inventory system**:
  - `Inventory` autoload (`scripts/Inventory.gd`) holds `items: Array[InventoryItemData]` and emits `inventory_changed` on every mutation. `_ready()` currently seeds temporary test items from `resources/*.tres`.
  - `InventoryItemData` (`scripts/InventoryItemData.gd`) is a `Resource` with name, description, icon and `inspection_model` (a PackedScene whose root must be `Node3D`). Items are authored as `.tres` files in `resources/`, each pointing at a `scenes/*_preview.tscn` wrapper around a model.
  - `scenes/InventoryUI.tscn` / `scripts/InventoryUI.gd`: CanvasLayer with a NAVIGATING/INSPECTING state machine; Q/E cycle items, Enter inspects, Esc goes back. The 3D preview lives in a SubViewport whose `PreviewWorld` node runs `InventoryInspectViewer.gd` (arrow-key rotation of `ItemPivot`, PageUp/PageDown or mouse-wheel zoom).
  - `scripts/WorldItem.gd`: pickup that adds its `item_data` to `Inventory` on `interact()` and frees itself.
  - Current wiring gaps: `InventoryUI.tscn` is not instanced in `world.tscn`, and the player's interact logic only queries the `npc` group, so `WorldItem.interact()` is not yet called by anything.
- **Shaders** (`shaders/`): `ps1_combined.gdshader` merges the three standalone experiments (`jittershader` screen-space vertex snap, `vertex_wobble` view-space snap, `affine_warp` affine UVs) with per-effect toggles — prefer it for new materials.

## Real-world map pipeline (`tools/map_import/`)

`models/zona_mapa.glb` is a real area of Zapopan built from OpenStreetMap with OSM2World 0.4.0 (Java). It is gitignored (~47 MB): the game only loads the chunks in `resources/map/cuadros/`, which are committed. Regenerate the .glb with the commands below before running `split_cuadros.gd`. The bbox lives in `tools/map_import/area.env`. `README.md` has the user-facing (Spanish) project overview and `docs/mapa/README.md` the full map guide (keep it in sync when the map changes; `docs/.gdignore` keeps its screenshots out of the Godot import).

```bash
bash tools/map_import/fetch_osm.sh      # Overpass -> data/map/area.osm (needs a User-Agent; falls back to mirrors on 504)
python3 -I tools/map_import/fetch_denue.py  # INEGI DENUE -> data/map/denue_puntos.json (stores/puestos)
python3 -I tools/map_import/fetch_google_buildings.py  # streams Google Open Buildings tile 843 (~1.7 GB, ~3 min), keeps only the bbox -> data/map/google_buildings.csv
tools/map_import/bin/venv/bin/python -I tools/map_import/fetch_satelite.py  # tree crowns + grass score -> data/map/satelite_* (venv: rasterio numpy scipy)
bash tools/map_import/build_glb.sh      # downloads OSM2World to tools/map_import/bin/ (gitignored, ~450 MB), runs prepare_osm.py, writes the .glb
godot --path . --headless --import      # runs scripts/map/MapPostImport.gd on the .glb
godot --path . --headless -s tools/map_import/split_cuadros.gd  # one .scn per chunk -> resources/map/cuadros/ (what the game loads)
godot --path . scenes/map_test.tscn     # walk the map
```

- `prepare_osm.py` crops ways to the bbox (+30 m), gives buildings without height 1–2 levels, a flat roof and a facade color (deterministic per OSM id), applies `data/map/overrides.json` (`"way/<id>": {tag: value|null}` — manual fixes from looking at Street View), and writes `<bounds>` so the model origin is the bbox center.
- `tools/map_import/osm2world.properties` is appended to OSM2World's `standard.properties`; OSM2World must run from its own folder because texture paths are relative.
- `build_glb.sh` runs OSM2World with `--lod 2`: below 2 OSM2World drops sidewalks and kerbs. LOD 2 would add 3D windows (GLASS/PLASTIC meshes); `prepare_osm.py` tags every building `window=no`, which keeps the LOD 1 materials (`Plaster002`/`Concrete034`). Once, it downsizes OSM2World's own textures to 256 px with ImageMagick and strips their ICC profiles (a gray ICC on 3-channel JPGs, e.g. Plastic010, made Java abort the whole export). Result: ~22 MB. `tools/map_import/bin/.gdignore` keeps Godot from importing OSM2World's bundled models/textures. OSM2World skips meshes that fail instead of exiting with an error, so the script checks `bin/osm2world.log` and fails if the .glb has no `Building` nodes.
- `MapPostImport.gd` (set as `import_script/path` in `zona_mapa.glb.import`) swaps every material for a `ps1_combined` ShaderMaterial (tint = original albedo color, `use_vertex_color = true` because OSM2World stores each house's `building:colour` as vertex color), adds trimesh collision except to vegetation, and sets `visibility_range_end`. The import keeps textures embedded (`gltf/embedded_image_handling=3`).
- Editing `MapPostImport.gd` does **not** trigger a reimport, and neither does `touch`: delete `.godot/imported/zona_mapa.glb-*` and run `--import` again. If an import fails, Godot writes `valid=false` into `zona_mapa.glb.import` and never retries; delete that line.
- OSM only has ~970 buildings here (one housing development north of the center); Microsoft footprints have even fewer (~140). `prepare_osm.py` fills the gaps with Google Open Buildings (CC BY 4.0): it keeps confidence ≥ 0.70 and area ≥ 20 m², skips any footprint that overlaps an OSM building, and adds the rest as ways with ids from `2*10**15` and `source=Google Open Buildings v3`. Result: ~7,900 buildings.
- The post-import merges the ~18k OSM2World meshes into 128 m chunks (one ArrayMesh per material per chunk, vegetation in a separate chunk without collision): ~200 nodes, ~85 draw calls. Per-building nodes and OSM ids don't survive the import.
- **Streaming**: `map_test.tscn` does not instance `zona_mapa.glb`. `split_cuadros.gd` saves each chunk as `resources/map/cuadros/cuadro_<x>_<z>[_vegetacion].scn`, shares the 15 materials as `materiales/*.res`, and writes `indice.json` with each chunk's real XZ extent. A mesh is assigned to the chunk of its center, so long roads and power lines make some chunks up to ~1.2 km wide. `scripts/map/MapStreamer.gd` (`Mapa` node, `target_path` = Player) loads synchronously the chunks within `load_radius` (300 m, measured to the extent rectangle) at start, then loads the rest with `ResourceLoader.load_threaded_request`, and frees the ones beyond `unload_radius` (400 m). About 40 of the 200 chunks are loaded at a time. `MapPuntos` streams stores the same way at runtime (250/320 m) but shows all of them in the editor. The chunks must be regenerated after every reimport of the .glb. In the editor, `map_test.tscn` shows no map, because MapStreamer is not `@tool`.
- **Drone mode**: the `Dron` node (`scripts/map/MapDron.gd`) in `map_test.tscn` starts active (`iniciar_en_dron`). It flies at a fixed `altura` (30 m) at `velocidad` (15 m/s, Shift ×3) with the camera pitched down; WASD moves it, and mouse or Q/E rotates it. Fog drops to `niebla_dron` while flying. **V** switches to the player, who is frozen while flying and lands under the drone via a downward raycast (street or roof). `MapStreamer` and `MapPuntos` use `Dron` as `target_path`; when not flying, the drone follows the player.
- The OSM2World textures are downsized to 256 px and forced to PNG32 or color JPG; gray+alpha PNGs make Java fail with `Unknown image type 0` and OSM2World silently drops every mesh using the texture atlas.
- **Facades**: `MapPostImport.BUILDING_ROLES` maps the only two building materials at LOD 1 (`Plaster002` walls, `Concrete034` flat roofs; Concrete034 is also used by sidewalks, so it only applies to meshes under a `Building*` node) to `shaders/ps1_facade.gdshader`. That shader picks a random tile per 2.5 m bay and level from `textures/map/fachadas.png` (row 1 = ground floor: door/cortina/window/zaguán; rows 2–3 deteriorated) and tints the wall part (`fachadas_mascara.png`) with the vertex color. The textures come from `python3 -I tools/map_import/make_textures.py`, either `--estilo dibujado` (default, all hand-drawn) or `--estilo fotos` (wall plaster, door, shutters and roofs cropped from CC0 Poly Haven photos downloaded to `tools/map_import/bin/texturas_cc0/`; windows are still drawn). Chunk materials reference these PNGs by path, so after regenerating them a plain `--import` is enough. Rows 2–3 of `fachadas.png` are the deteriorated variants (drawn in both styles; `draw_args` also takes `(color, [(x, y), ...])` lines/polygons). The current textures use `--estilo fotos`. The same script writes `grietas.png`, `suelo.png` (dark green base grass), `banqueta.png` (sidewalk), `pasto*.png`, `asfalto.png`, `empedrado.png`, `mata_pasto.png` and `arbol.png`. `MapPostImport.GROUND_TEXTURES` draws OSM2World's `TERRAIN_DEFAULT` and non-building `Concrete034` with `shaders/ps1_suelo.gdshader` and those textures (world-space tiling every `tile_size` m, mipmapped, jitter/wobble off); changing that dict needs a reimport plus `split_cuadros.gd`. The `Suelo` plane in `map_test.tscn` (5 cm under the map) uses the same shader and texture: where they overlap the image is identical, so z-fighting doesn't show. Photo textures through `ps1_combined` (`filter_nearest`, no mipmaps) shimmer badly on the ground. The other flat ground materials (`MapPostImport.FLAT_GROUND`: asphalt, grass, water...) keep `ps1_combined` with jitter/wobble off: wobble moves vertices up to 2.5 cm in depth, so distant roads sank under the non-wobbling dirt/sidewalk and flickered. The PS1 vertex stage is shared through `shaders/ps1_vertex.gdshaderinc`, which `ps1_combined` also includes.
- **Stores (puntos)**: `python3 -I tools/map_import/fetch_denue.py` downloads INEGI's DENUE for Jalisco (~40 MB zip, Latin-1 CSV), keeps the bbox and maps SCIAN codes to tipos (`TIPOS_SCIAN`; `Semifijo` = puesto, OXXO by name) -> `data/map/denue_puntos.json`. Google Maps/Places can't be used: their terms forbid extracting places. `data/map/puntos.json` is for manual points plus an `omitir` list of `origen` ids to drop bad DENUE/OSM points; `prepare_osm.py` also takes shop/amenity points from OSM. It keeps only one point per tipo within 80 m (150 m for `tienda`, `DUPLICATE_DIST_TIPO`) (priority manual > DENUE > OSM), snaps each store to the house it's in or the nearest one within 15 m (houses > 300 m² are skipped: Google merges whole rows), prefers houses on the point's side of the street (any side if the point is in the carriageway), recomputes the facing from the house it snapped to (prefab front = +Z) and removes that house; `puesto*` don't remove houses and always go on the sidewalk, front `PUESTO_GUARNICION` behind the kerb. Then `alejar_de_calles` pushes every store/puesto (real footprint from the huellas) out of the carriageway + sidewalk of every `BLOCK_STREET_TYPES` street (service is skipped: gas-station/parking driveways; a puesto ignores its own street), so DENUE points in the middle of a street end with the facade on the nearest sidewalk edge. The result goes to `resources/map/puntos_mapa.json` with local x/z, `rotacion_y`, and the lot's `ancho`/`fondo`. `scripts/map/MapPuntos.gd` (`Puntos` node in `map_test.tscn`) instantiates `prefabs[tipo]`, or a colored placeholder box, at runtime; its children are not saved to the scene. Changing puntos requires rerunning `build_glb.sh` and reimporting, because the replaced houses disappear from the .glb.
- **Sketchfab models**: `SKETCHFAB_TOKEN=... python3 -I tools/map_import/fetch_sketchfab.py` downloads the models listed in `MODELS` (key = folder under `models/`: `tiendas/`, `casas/`, `props/`, `objetos/`) as `scene.gltf`, shrinks their textures to 256 px, writes a `.import` with `scripts/map/TiendaPostImport.gd` and appends the credits to `CREDITS.md` (one section per top folder). `TiendaPostImport` swaps materials for `ps1_combined` (albedo only), can crop scenes listed in `RECORTES` (currently none) and reduces models in `MAX_TRIANGULOS` with `ImporterMesh.generate_lods` (meshoptimizer; photogrammetry scans full of UV seams stop at ~1/8). Blender decimation and `SurfaceTool.generate_lod` were tried and wreck scanned models. `fetch_sketchfab.py` only shrinks textures of fresh downloads (mogrify rewrites files even when the size doesn't change). Removed at the user's request after testing (scans looked broken or were too heavy): House Porch Toluca, Mexican Auto Repair Shop (taller), Carrito de Tamales and the "Tacos" stand. Five requested models can't be downloaded through the API and were dropped: Street buildings, Taco – Mexican Food (paid), Telmex Payphone, Mexican Construction Worker, Chivas.
- **Only baked models are in git**: the game loads `models/<grupo>/<modelo>/<modelo>.scn`, written by `godot --path . --headless -s tools/map_import/hornear_modelos.gd` from the imported `scene.gltf` (already reduced and with PS1 materials; LODs stripped, compressed, UID kept across rebakes). `scene.gltf`, `scene.bin`, their `.import` and the unused texture maps (normal, metallicRoughness, emissive, occlusion, specular) are gitignored; only `textures/*_baseColor`/`_diffuse`, `LICENSE_sketchfab.txt` and `preview.png` are committed next to the `.scn`. To change a model's reduction, tints or materials: re-download with `fetch_sketchfab.py` (it re-downloads any folder without `scene.gltf`), `--import`, then rerun `hornear_modelos.gd` (and `separar_pack.gd`/`separar_simi.gd` if it's one of those). `map_test.tscn` references the `.scn` files. The originals are still in git history (commits before 2026-10-27).
- **Game assets (not placed yet)**: `fetch_sketchfab.py` also downloads `models/personajes/` (NPCs, zombies, Simi), `models/armas/`, `models/interiores/` and inventory/mission objects in `models/objetos/` (list and status in `docs/especificaciones.md` §10). `TiendaPostImport.TINTES` repaints materials by name (tejuino, trapo); `GRUPOS_PS1_EQUIPO` (personajes, armas, objetos, interiores) use the team's values `snap_resolution` 80 and `wobble_resolution` 80; affine stays off everywhere because Sketchfab texture atlases smear with the affine warp (tested even at `warp_strength` 8). `SIN_WOBBLE` turns wobble off for tiny objects (the 2.5 cm view-space snap collapsed the 1 cm pill into a triangle). The PS1 material replaces the original inside the mesh (not as a surface override), so baked `.scn` files don't reference the gitignored normal/roughness maps. Only `mochila` and `mazapan` are split from the Mexican Starter Pack; the pack itself isn't baked (`hornear_modelos.SOLO_PIEZAS`) and its other textures are gitignored. Sketchfab only offers the Mexican Starter Pack as one download: `godot --path . --headless -s tools/map_import/separar_pack.gd` saves each piece as `models/objetos/mexican_starter_pack/<pieza>.scn`; `separar_simi.gd` saves the dancing Simi costume (Mixamo rig, `bailar` loop) from the Similares kiosk as `models/personajes/dr_simi/simi_botarga.scn`. Rerun both after reimporting those models. `python3 -I tools/fetch_cc0.py` downloads the CC0 Quaternius Universal Animation Library 1+2 to `models/animaciones/` (own humanoid rig, not Mixamo: use Godot retargeting). `godot --path . -s tools/map_import/capturas.gd [-- --todas]` (needs a window) writes `preview.png` into each model folder (`<name>_preview.png` next to loose `.scn`); skinned models are framed by their bones because their mesh AABB ignores the pose. `fetch_sketchfab.py` waits and retries on HTTP 429.
- **Store models**: assigned in `map_test.tscn` → `Puntos.prefabs` (oxxo, tienda = Tienda 3B, farmacia = Farmacia Guadalajara, puesto_tacos = Cara1 Puesto de Tacos, gasolinera = Pemex Low Poly, puesto = Low Poly Street Food Cart, alto = Señal Alto) with `prefab_rotacion` in degrees so the storefront faces +Z. `MapPuntos` scales each model uniformly to `prefab_ancho[tipo]` metres of frontage (never stretched to the lot: Google lots can be thin strips and squashed models), puts the facade on the lot's street edge and lets it grow backwards and sideways; `prepare_osm.quitar_edificios_encimados` then removes every OSM/Google building, and every model-house lot, that overlaps a store's real footprint (inset 0.3 m). Footprints come from `data/map/huellas_tiendas.json`, written by `tools/map_import/huellas_tiendas.gd` (run by `build_glb.sh`; it calls `MapPuntos.huella_modelo`, so changing `prefabs`/`prefab_ancho`/`prefab_rotacion` only needs a rebuild; it also writes `casas`: native frontage/depth of each `Casas.modelos` via `MapCasas._preparar_modelo`), adds a box collision, and turns off its shadows beyond 250 m. Tipos in `MapPuntos.LOCALES` (taqueria, tortilleria: Sketchfab has no usable models) are built from boxes by `_make_local`: lot-sized (min `LOCAL_MIN`) shop with a recessed open entrance, rolled-up cortina, counter, painted sign with the name and an awning for taquerías. `prepare_osm.py` also writes an `alto` at one of every 20 street corners (`place_altos`: OSM nodes with ≥ 3 street segments; on the driver's right 6 m before the crossing, facing traffic) straight into `puntos_mapa.json`. `oxxo_abandonado`, `oxxo_letrero`, `oxxo_mexican`, `barrio_mexicano`, `tacos_props`, `casas/multifamiliar` (no apartment towers are tagged in OSM yet) and `models/objetos/*` (Takis, 1 peso coin, Jarritos) are downloaded but unused.
- **Colonias**: OSM has no neighbourhood polygons. `fetch_denue.py` also writes `data/map/denue_colonias.json` (`[lat, lon, colonia]` of every DENUE business in the bbox, names normalized with `COLONIA_ALIAS`). `prepare_osm.Manzanas` rasterizes the streets of `BLOCK_STREET_TYPES` (not service/footway, so cotos aren't split) at 1 m, 4 m half-width, extends dead-end privadas up to 50 m until they hit another street, and flood-fills: each region is a manzana. A manzana's colonia is the most common among its DENUE businesses, else the majority of its houses' 9-nearest-business votes; `data/map/colonias.json` (`"lat,lon": "COLONIA"`) overrides it. Colonias never mix inside a manzana. `build_glb.sh` writes `data/map/colonias_debug.png` (manzanas colored by colonia, gitignored) and prints the colour legend.
- **Model houses** (`data/map/casas.json`: colonia → pisos (`"1"`, `"2"`, `"*"`) → weighted model list; `"*"` colonia = every other colonia and manzanas without one, same Urbi/Semi Residencial mix as HSJ/PSM; `_proporcion` = fraction replaced, `"AGUA BLANCA INDUSTRIAL"` has 0 because its footprints are warehouses; only Parques del Bosque uses Mexican House 3): `prepare_osm.place_casas` runs after the stores, takes each house (25–1500 m², ≤ 30 m from a street), finds its nearest street segment and measures the footprint along it (u) and away from it (v). It ignores individual Google footprints (they overlap each other): per block face (straight street segment, side, manzana) it unions the houses' u-intervals (gaps < `HUECO_MAX` 10 m merged, longer gaps stay empty, store footprints cut the run) and fills each run with models side by side at their native frontage (`huellas_tiendas.json` `casas`), one shared scale within `CASA_ESCALA` 0.8–1.25 (so `MapCasas` fills each lot exactly), only models whose depth fits the block. `_proporcion` is decided per face. Faces are processed longest first; a lot is dropped if it overlaps an existing lot sideways (same row or corner; back-to-back lots with facades > ~135° apart, `ESPALDA_COS`, may overlap at the back — the user is fine with that) or reaches into another street's carriageway + sidewalk (`invade_calle`). Every house of a replaced face plus any building under a new lot (`quitar_edificios_encimados`, grid index `Rejilla`) is removed. Facade alignment: per (street way, side, manzana) every facade goes on the median front distance of all houses of that group (not only replaced ones), never closer than the street's carriageway + sidewalk (`borde_banqueta`) + 0.3 m. Replaced houses are removed from the .glb; the lots go to `resources/map/casas_mapa.json` (facade-centre x/z, `rotacion_y`, `ancho`, `fondo`, `pisos`, `color`, `colonia`). `scripts/map/MapCasas.gd` (`Casas` node, streams 64 m cells around `Dron` like MapPuntos) bakes each model into one ArrayMesh per material and draws every cell as one `MultiMeshInstance3D` per model with per-instance colour, plus one StaticBody with a box per house and side bardas when the model is narrower than its lot. Models are scaled uniformly to the lot frontage within 0.8–1.25 (`ESCALA_MIN/MAX`, same range as `prepare_osm.CASA_ESCALA`) (`modelo_escala` fixes models in other units: mexican_house_3 ×1.5). The Urbi model is one mesh with 6 houses in a row; `modelo_rango_x` keeps the triangles of one house each (`urbi_1p_a/b/c`, `urbi_2p_a/b/c`; facade faces −Z, so `modelo_rotacion` 180). The Urbi has no walls between its 6 houses, so split houses were hollow: `nucleo[modelo]` adds a box of the house colour (height fraction 0.62/0.72, 0.12 m inset, 1.5 m back from the front so recessed facades stay visible) to the bardas MultiMesh. House colours come from `prepare_osm.CASA_PALETTE` (more saturated than `PALETTE`; the shader multiplies by the texture shading and fog washes them out). `quitar_piso` drops triangles within 0.4 m of the floor (sidewalk/garden patches) and the facade is placed from the AABB of what remains (`_aabb_fachada`). `shaders/ps1_casa.gdshader` recolours only texels near `muro_key[modelo]` (chroma distance < `muro_tol`) with the instance colour, keeps door/window/trim colours, discards alpha < 0.5, has wobble off and `cull_disabled` (Mexican House 3 has flipped faces). `modelo_distancia` can cap the draw distance of heavy models. Measured on the user's laptop: ~190 FPS at street level in Haciendas de San José, ~140 in Parques del Bosque, ~160 FPS aerial.
- **Minimap**: `tools/map_import/make_minimapa.py` (run at the end of `build_glb.sh`, ~2 s) rasterizes `bin/area_prepared.osm` plus the lots of `casas_mapa.json` and `puntos_mapa.json` at 1 m/px into `textures/map/minimapa.png` (stdlib only, reuses `prepare_osm.local_xz`/`write_png`) and writes `resources/map/minimapa.json` (top-left corner in map metres). The `Minimapa` CanvasLayer (layer 2, above the dither) in `map_test.tscn` runs `scripts/map/MapMinimapa.gd`: a round GTA-style radar in the top-right corner, drawn by `shaders/minimapa.gdshader` and rotated so the camera's forward points up, with the player arrow (`Frijol` heading), an N marker and a coloured square per store (`alto` excluded). It follows `Dron` and zooms out (`radio_dron`) while flying (`MapDron.volando()`).
- **Streets** (`prepare_osm.calles_y_banquetas`, runs right after the Google buildings): every street gets `width` = carriageway (`ANCHO_CALLE` by highway) + sidewalks (`BANQUETA`, only `BLOCK_STREET_TYPES`), tagged `sidewalk=*`, `sidewalk:<side>:width`, `sidewalk:<side>:surface=concrete` (→ `Concrete034`, drawn as banqueta; without the surface tag OSM2World uses asphalt). Where the median facade distance of that street side is closer, the sidewalk then the carriageway shrink (`BANQUETA_MIN`, `ARROYO_MIN_MEDIO`). OSM `width` is the total including sidewalks. The returned `perfil` (half carriageway, left/right sidewalk per way) sets the house setback (`place_casas`), puestos and altos. **Medians**: two oneway ways with the same name (or both unnamed and same highway), opposite direction, 6–40 m apart on ≥ 60 % of samples are a pair: each carriageway is half + 1 m, sidewalk only on the outer side, and between them a `landuse=grass` polygon plus a 12 cm `barrier=wall` kerb (ids from `3*10**15`, `source=camellon taquito`), cut only where another street leaves toward the median side.
- **Satellite** (`fetch_satelite.py`, the only non-stdlib script; venv in `tools/map_import/bin/venv`, raw downloads cached in `bin/satelite/`): samples Meta/WRI Canopy Height (1 m, EPSG:3857 tile by zoom-9 quadkey) and the 5 clearest Sentinel-2 L2A scenes per season from Element84 Earth Search onto the minimap grid (1 m/px, bbox − 30 m, inverse of `local_xz`). Earth Search's `earthsearch:boa_offset_applied` isn't reliable, so the −1000 DN offset is detected from the data (blue 1st percentile > 1000). Grass score = max(ramp of rainy-season median NDVI 0.30–0.45, ramp of dry-season BSI 0.17–0.25); urban pixels sit at NDVI ~0.1–0.2 / BSI ~0.1. Crowns = local maxima of the smoothed CHM ≥ 3 m with rainy NDVI ≥ 0.25 nearby. `make_vegetacion.py` (run by `build_glb.sh` before the minimap, stdlib) removes buildings, lots, carriageways and sidewalks from the score, adds medians -> `textures/map/pasto_mascara.png` + `resources/map/pasto_mascara.json`, and drops/moves crowns -> `resources/map/arboles_mapa.json`; it also writes `data/map/calles_debug.png` (gitignored).
- **Ground**: `ps1_suelo` has `modo` 0 (texture), 1 (base + grass where the mask says, used by `TERRAIN_DEFAULT` and the `Suelo` plane), 2 (all grass, OSM `GRASS`: medians, parks). `suelo.png` is now dark green grass (the area isn't desert) and `pasto.png`/`pasto_seco.png` are lighter, mixed by world noise. `SueloPasto.configurar` sets the mask uniforms for both MapPostImport and the `Suelo` plane (`MapPasto.suelo_path`); MapPostImport is editor-only, so shared code can't live there. `GROUND_TEXTURES` also maps `ASPHALT` → `asfalto.png` and `PAVING_STONE`/`SETT` → `empedrado.png`. New ground textures need `mipmaps/generate=true` in their `.import`.
- **Trees and tufts**: `MapArboles.gd` (`Arboles`, follows `Dron`, 64 m cells) draws procedural low-poly trees (2 variants) as MultiMesh with `ps1_arbol` (atlas `arbol.png`: bark left, leaves right tinted by instance colour) and a cylinder collision per trunk. `MapPasto.gd` (`Pasto`, follows `Player`, hidden while flying) scatters crossed-quad tufts (`ps1_pasto`, `mata_pasto.png`) in 16 m cells within 40 m where the mask ≥ 0.6, deterministic per cell.
- **Deterioration (post-apocalyptic)**: `shaders/ps1_deterioro.gdshaderinc` (included by `ps1_facade`, `ps1_suelo`, `ps1_casa`, `ps1_combined`; it also owns `hash`/`ruido`, so those shaders must not redefine them) reads the global shader uniforms `deterioro` (max 0–1), `deterioro_escala` (zone noise size, m) and `deterioro_grietas` (`textures/map/grietas.png`, mipmapped) from `project.godot` `[shader_globals]`. `zona_deterioro(xz)` = world noise × `deterioro` (never below 25 %). `muro_sucio` (faded paint, drips, ground grime, soot, fallen plaster showing block/brick), `mugre` (light grime), `vidrio_roto`, `piso_roto` (cracks, potholes on asphalt, dust, broken sidewalk slabs). `ps1_facade` picks rows 2–3 of the now 4×4 `fachadas.png` (broken/boarded/blocked windows, boarded door, rusty cortina with graffiti) with probability ∝ zona. `ps1_suelo.piso_tipo` (set from the 4th element of `MapPostImport.GROUND_TEXTURES`: 1 asphalt, 2 sidewalk, 3 cobblestone) and dry grass grows with zona. `ps1_casa` gets `ventanas` UV rects per model from `MapCasas.ventanas_uv` (glass isn't one colour: Urbi tinted, Semi Residencial interior photos; Mexican House 3 has none). `ps1_combined.deterioro_modo` (default 0, so nothing else changes): `MapPuntos` sets 1 on duplicated prefab materials and on local boxes, 2 on local walls/placeholders. Colour grading is in `dittershader` (`desaturacion`, `tinte`, `contraste`, `vineta`; neutral defaults, set in `map_test.tscn` only). Changing `GROUND_TEXTURES`/facade texture layout needs reimport + `split_cuadros.gd`.
  `scripts/map/Deterioro.gd` (`Deterioro.zona(x, z)`) is the same formula in GDScript (integer hash `hash_entero`, because the `sin()` hash differs between float32 GPU and float64 GDScript; checked to match within 0.002). It reads the globals from `ProjectSettings` (`RenderingServer.global_shader_parameter_get` is editor-only); call `Deterioro.configurar(maximo, escala)` to change both at runtime. If you change `zona_deterioro`, change both. Planned: zombie spawn density × `Deterioro.zona` (`docs/especificaciones.md` §4.8).
- **Warehouses (bodegas)**: `prepare_osm.place_bodegas` (runs after the stores, before the houses; output `resources/map/bodegas_mapa.json` via `--salida-bodegas`) takes unnamed `building` in `BODEGA_TIPOS` with area ≥ `BODEGA_AREA_MIN_INDUSTRIAL` (100 m²) in `BODEGA_COLONIAS` (Agua Blanca Industrial: only 19 buildings in the bbox) or ≥ `BODEGA_AREA_MIN` (600 m²) anywhere, fits the minimum-area rectangle of the convex hull, fronts it to the nearest street, splits sides > `BODEGA_LARGO_MAX` (70 m) into naves with `BODEGA_PASILLO` aisles, trims each nave so no street axis + half carriageway + `BODEGA_BANQUETA` crosses it (`recortar_nave`; drops it if a side goes under `BODEGA_LADO_MIN`), and skips naves that hit another nave or a store. The footprint is removed only if a nave was placed; nave footprints join the store footprints, so house rows stop at them. Result: 89 naves from 61 footprints, mostly La Gigantera and El Mante. `scripts/map/MapBodegas.gd` (`Bodegas` node, 64 m cells around `Dron`) builds each one hollow with SurfaceTool: corrugated walls (`lamina.png`, `ps1_combined` `deterioro_modo` 3 = rusty sheet metal, vertex colour), 8-segment arched roof with trusses (panels missing by zona), concrete floor (`ps1_suelo` `piso_tipo` 2). Collision is per wall piece/pier/lintel/roof segment and per prop (one box per run of consecutive racks), never a solid box. Cells are built one at a time on a `WorkerThreadPool` task (`_crear_celda` only builds meshes and returns the collision boxes as data); `_cuerpo` then creates the StaticBody shapes on the main thread, because the physics server isn't touched from the worker thread. That keeps a cell load under ~1 ms on the main thread (it was up to 12.6 ms). Only the first load in `_ready` is synchronous; high zona punches a hole in a side wall. Inside: rack rows (only every `HILERAS_CADA` = 2nd row, at the user's request: there were too many shelves; 3.2 m aisle pitch, 5 m clear behind the front), rusty shelves and boxes as MultiMesh, drawn only within `adentro_end` (80 m). If the manzana is deeper than `COTO_FONDO` (24 m) and > `COTO_CASAS_FUERA` (15 %) of its building centroids are nearer a public street, those cells stay public (privadas inside normal blocks). `place_casas(cotos=)` doesn't replace houses whose nearest street is public but that sit in a coto cell. `place_bardas` (after the houses) samples every street side every `BARDA_PASO` m at `borde_banqueta + FACHADA_HOLGURA`: `coto_calle` where the cell 1.5 m inside is a coto's, `baldio` (only `BLOCK_STREET_TYPES`) where nothing is built for `BALDIO_FONDO` (15 m) inward, runs ≥ `BALDIO_MIN` (12 m), dropped if ≥ 50 % of the strip has raw `satelite_pasto.png` ≥ 153 (`pasto_mascara.png` is made later). Walls behind houses and between cotos (raster owner boundaries) were removed at the user's request: they wrapped every privada with jagged, many-angled walls. `bodega`: convex hull of each original footprint's naves (`grupo`, popped before writing `bodegas_mapa.json`) + `BODEGA_MALLA` 3 m. `osm`: the OSM walls, removed from kept_ways so OSM2World doesn't draw them. Accesses of cotos made only of `service` ways (parking, gas stations) get no caseta. 159 gate nodes → 117 plumas, 50 casetas. ## Conventions / gotchas

- PS1 shaders must write `POSITION` unconditionally (`ps1_vertex()` returns the unsnapped clip position when `jitter_enabled` is false). A spatial shader that writes `POSITION` only inside an `if` leaves the mesh invisible when the branch isn't taken. The original `ps1_combined` had this bug; `shaders/jittershader.gdshader` still does. Huge meshes (the 1900 m `Suelo`) need jitter/wobble off, otherwise vertex snapping distorts them near the camera.
- `pkill -f <pattern>` from the Bash tool also kills the tool's own shell when the pattern appears in the command line; use a pattern that can't match itself (e.g. `fetch_sat[e]lite`).
- Chunk `visibility_range_end` is 250 m plus half the chunk's AABB diagonal, because Godot measures it to the AABB center and some chunks are 800+ m wide.
- Input actions are defined in `project.godot` (`move_*`, `camera_*`, `jump`, `sprint`, `inspect_*`, `inventory_*`). Note `E` is bound to both `camera_right` and `inventory_next`, and arrow keys to both `move_*` and `inspect_*`.
- Resources are referenced by `uid://`; keep each `.gd.uid` file alongside its script when moving/renaming, or edit via the Godot editor.
- `scenes/world.tscn` and `scripts/Inventory.gd.uid` are listed in `.gitignore` but are already tracked, so changes to them still show up in git.
- `scenes/InventoryUI.tscn*.tmp` files are editor save leftovers, not real scenes.
